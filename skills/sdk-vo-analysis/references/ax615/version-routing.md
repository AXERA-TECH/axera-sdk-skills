# AX615 VO SDK 版本探测与路由

> 本文件定义 `sdk-vo-analysis` 的诊断与配置生成两条流程共用的版本识别和证据降级规则。
> 内化资料的机器可读版本以 [version-manifest.json](version-manifest.json) 为准。
> 涉及实现行为的固定标注为：**SDK V3.14.0 实现行为，需按版本核验**。

## 1. 版本来源优先级

按以下顺序选择运行中 VO 的版本证据：

1. `/proc/ax_proc/vo/display_status` 中的 `[SDK version]:` 行：代表当前运行的 VO 驱动，优先级最高。
2. `/proc/ax_proc/version` 或 `AX_SYS_GetSdkVersion()`：代表系统/内核 SDK；部分系统可能没有该节点。
3. `libax_vo.so` 初始化日志中的 `[SDK version]:`：代表用户态 VO 库，且可能受日志级别影响。
4. `dmesg` 中其他模块的 `[SDK version]:`：只作同一系统构建批次的旁证，不代表 VO 驱动。
5. 客户口述、构建树版本或 sample 版本：仅作补充证据。

`display_status` 的版本行不是固定在物理首行；应扫描文本查找 `[SDK version]:`。模块名可能不同，解析时不要写死。版本 token 支持 `Vx.y.z`（前导 V 可省略）以及构建后缀：下划线变体/时间戳（`V3.10.0_2771`、`V3.14.0_20260915123456`）和 `-`/`+` 附加标识（`V3.14.1-rc1`）。**后缀完整保留在 `raw_version`/`build_variant` 字段，主版本 `version` 始终归一化为 `Vx.y.z`；构建变体不改变版本匹配结果**。多段点分数字（`192.0.2.1`、`3.14.0.1`）不是版本 token，脚本会跳过。

以上关于 proc/log 输出形态和来源优先级的行为事实均为：**SDK V3.14.0 实现行为，需按版本核验**。

## 2. 探测命令

优先让客户提供完整文件，再运行：

```bash
python3 scripts/detect_sdk_version.py --display-status display_status.txt --system-version ax_proc_version.txt --dmesg dmesg.txt --text '客户口述或其他版本信息' --json
```

也可单独解析：

```bash
python3 scripts/detect_sdk_version.py --display-status display_status.txt
python3 scripts/detect_sdk_version.py --text 'SDK V3.12.0' --json
python3 scripts/detect_sdk_version.py --known --json
```

脚本退出码区分「未命中」与「未执行成功」：`0` 已识别版本（或 `--known`）；`1` 输入/文件读取错误（未执行）；`2` 提供的内容里没有版本痕迹；`3` 给了文件但未解析出版本。`--json` 输出关键字段：`detected_version`（归一化主版本）、`raw_version`（原样 token，含构建后缀）、`build_variant`、`match`、`conflict`、`in_version_history`、`history_version`、`history_unverified`、`history_vo_changes`、`policy.d_e_usage`。

## 3. 匹配与证据路由

`match` 只有三种取值：`same`（归一化主版本 == 内化基线 V3.14.0，构建变体后缀不影响判定）、
`different`（识别出版本，但不是 V3.14.0）、`unknown`（未能识别版本）。`conflict` 是**独立布尔标记**
（多个来源版本不一致，`conflict=true` 且带 `conflicts` 列表），不属于 `match` 取值；两者可同时出现，
例如 `match=same` + `conflict=true`（display_status 为 V3.14.0，dmesg 旁证为 V3.12.0）。

| 探测结果 | D/E 级内化资料用法 | 输出要求 |
|---|---|---|
| `match=same`：运行版本与 V3.14.0 主版本相同 | 可作为已内化行为判据引用，但仍保留固定版本标注 | 注明探测来源和 `SDK V3.14.0 实现行为，需按版本核验` |
| `match=different` 且版本在 `version_history` 中 | 按第 6 节路由：该区间已收录记录未发现相关差异时 D/E 级行为判据可引用（附"已收录记录未发现相关差异，目标环境仍需核验"说明，**不得表述为行为保证**）；命中差异点时按差异点版本表述 | 明确写出客户版本和内化版本不同；注明该版本的 VO 差异点（脚本 `history_vo_changes` 字段 + `history_version`）；不适用时用客户头文件、版本文档、知识库、Gerrit 或实机重新核验 |
| `match=different` 且版本不在 `version_history` 中 | **V3 系列未收录版本同样降级**（脚本 `history_unverified=true`）：该区间未经核实，不给"无差异"背书（无提交记录同样不构成行为保证）；V2.x 及更早同理。D/E 级资料只能作为待验证假设 | 明示"该版本区间未经核实"，D/E 级结论标为待验证假设，须用目标版本头文件、知识库、Gerrit 或实机复核 |
| `match=unknown`：无法识别版本 | 未获用户同意前不得用 D/E 级资料继续版本相关诊断或配置；同意后只能作为临时基线 | 先声明“SDK 版本未知，当前内化资料基于 V3.14.0”，询问是否按 V3.14.0 继续；同意后标注“基于 V3.14.0，须按客户实际版本核验”，并继续收集 `display_status` |
| `conflict=true`：多个来源版本不一致 | 不构成独立 `match`，以最高优先级来源（`display_status` 的 VO 驱动版本）路由；其他值保留为冲突证据 | 同时列出冲突来源，提示可能存在系统、驱动或用户态库混装，不得静默选择 |

`policy.d_e_usage` 取值：`as-is-annotated`（`same`，可带固定标注引用）、`hypothesis-only`（`different` 降级）、`unknown-version-hypothesis`（未获同意的 `unknown`）、`known-only`（仅 `--known` 查询内化版本）。

A/B/C 级资料也要核对其发布版本；公开 API 名称和字段可直接核对，但版本不同不能假设实现行为完全一致。

## 4. 诊断与配置差异

- 诊断流程：版本不匹配或未知时，D/E 级结论降为“推测”，附客户可执行的核验步骤；怀疑版本缺陷时，知识库和 Gerrit 查询词必须带探测版本。
- 生成流程：版本不匹配或未知时，不使用 D/E 级资料生成“最终已验证配置”；可以输出候选值，但必须标记“基于 V3.14.0 内化资料，须在目标 SDK 重新核验”。预设名、结构体和 Python 包装以客户实际 SDK 为准。

## 5. 冲突与降级

- `display_status` 不存在时，先确认 VO 驱动是否已加载；节点缺失不能被解释为“版本无差异”，也不构成任何行为保证。
- `/proc/ax_proc/version` 不存在或 `AX_SYS_GetSdkVersion()` 失败时，继续使用 `display_status`；该失败本身不能判定 SDK 异常。
- `dmesg` 没有 VO 版本行属于可能情况，不能据此认定版本未知；仍应优先读取 `display_status`。
- 探测脚本只解析用户提供的文本或文件，不连接设备、不访问任何外部源码树（用户显式提供的文件可读），也不自动引入新知识。

### 多版本分析规则

1. **探测版本在 version_history 中 → 可分析**：D/E 级行为判据可直接引用，但必须结合该版本的差异点判断适用性（三个实质差异点：V3.1.0 Clip 限制、V3.5.0 VSYNC 事件机制、V3.11.0 数字 Coax 修复；行为摘要对应条目带版本注记）。引用时保留固定版本标注，并注明“该行为自 Vx.y 起引入/在 Vx.y 之前不同”。表中该区间无差异记录时，注明“已收录记录未发现相关差异，目标环境仍需核验”，**不得把无提交/无差异记录表述为行为保证**。
2. **探测版本不在 version_history 中 → 一律降级为假设**：包括 V2.x 及更早，**也包括未收录的 V3.y.z**（脚本给 `history_unverified=true`）。没有该区间的核实记录，就不能替它背书“无差异”；D/E 级资料只能作为待验证假设，须按目标版本重新核验（同 `different` 降级规则）。
3. **“无差异”仅指已收录记录未发现相关差异，不是行为保证**：表中“未发现差异记录”表示该区间已收录的 VO 相关记录（VO 公开头文件、官方 sample VO 配置等）中未发现差异记录；**没有差异记录不等于目标环境行为一致**——目标环境仍须按第 3 节核验。该结论只对表中已列版本成立，不得外推到未收录版本，也不代表整个 SDK 其他模块无差异。
4. **差异点版本注意事项**：
   - 客户版本 ≤ V3.0.0：Clip 配置对 RGB 信号生效，诊断偏色/灰阶问题时不能引用“Clip 仅 BT 生效”；
   - 客户版本 ∈ [V3.1.0, V3.4.0]：VSYNC 事件线程为旧机制，涉及回调线程时序的现象须按旧机制验证；
   - 客户版本 ≤ V3.10.0：数字 Coax 存在数据裁剪缺陷，Coax 数据异常优先建议升级到 V3.11.0+。
5. 匹配 `same` 时按当前基线 V3.14.0 引用；客户为 V3.13.0 时行为结论同样有效（知识保留自该基线），但标注仍写当前固定版本标注，并在结论中说明已收录记录未发现两版本 VO 相关差异、目标环境仍需核验（V3.13.0 在 version_history 中，属 `different` + 已收录记录未发现差异路径）。构建变体（如 V3.10.0_2771）按主版本 V3.10.0 入表，引用时把 `raw_version` 原样写进结论，便于客户对号。
