## 冲突与证据边界

1. 使用说明采用 `custom_test.sh`，知识库采用 `axera_test.lua/axera_test.sh`。以目标版本最终 `ota_check` 调用为准，不合并为固定脚本名。
2. Linux/QNX 的部署、工具和文件系统差异分别查阅对应知识库，不按另一系统的示例推导。
3. “先保护再写入”是设计约束；脚本列表中的前置 erase 必须结合运行调度核实，不能只复制列表。
4. 不支持独立 recovery 系统与支持 A/B 内容复制恢复并不矛盾，两者应分别判断。
5. M57 的状态细节不能直接作为 AX637 实现、缺陷或修复适用性的证明。
6. FAQ 是通用排查资料，未逐项核对修复提交和版本；实际修复状态以目标 SDK 证据为准。
7. 离线分析、模型评测、SDK 构建和实板验收分别记录；随包资料和用例不构成上述测试已通过的证明。
