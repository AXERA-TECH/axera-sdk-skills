# 现场材料与录音采集（Phase 1）

## 一、先整理已有材料

一键包先检查清单，压缩包确认成员路径、符号链接和展开大小后，解压到 skill 目录外的新证据目录；拒绝越界条目，原包只读。

| 材料 | 要确认什么 |
|---|---|
| 现象与复现 | 谁说话、谁听回声、触发操作、失败次数/试验次数 |
| 环境 | 芯片/板型、整套 SDK、编译所用对外头文件发布包、运行音频组件、OS、集成或独立模式、设备/实例 |
| 配置 | 期望设置、实际调用接口与完整配置、API 返回值/读回、目标设备 proc 分别保存，对外依据是否匹配版本 |
| 日志与对照 | 最后正常、首个异常、触发时刻；正常/异常素材、音量、处理开关是否相同 |
| mic/ref/output | 格式、采集位置、轮次、时间关系，文件是否写完 |

保留文件名、原始行号和录音区间，按当前疑问补采：版本不清查版本；布局疑问补板级说明和分声道单讲；启停异常采完整切换窗口。

## 二、读取运行状态

以下节点、Dump 位和 SaveFile 约定来自《AX AUDIO API 文档》V1.7（2026/07/13）§5、§2.1/2.2 和 §3。先核对客户版本；不匹配时补取对应版本说明。

基础材料先采 AI/AO；涉及编码、解码或最终发送流时再补 AENC/ADEC：

```bash
cat /proc/ax_proc/ai
cat /proc/ax_proc/ao
# 按需补采：
cat /proc/ax_proc/aenc
cat /proc/ax_proc/adec
```

正常、触发后异常、恢复后三个时点分别保存输出，记录采集时间、stdout/stderr、退出码和设备/轮次。按 `AiCardId/AiDevId`、`AoCardId/AoDevId` 或 `ChnId` 选目标行；保留原始文件，分析摘录另存。读取失败只表示材料未取得；已有读取阻塞时先处理，避免反复启动。

配置字段按 [diagnosis.md](diagnosis.md) 第二节核对；计数前后增量按 [delay.md](delay.md) 第四节分析。单次 proc 快照不能代替异常期间的连续录音。

### 按需补应用调用记录

只有 proc 无法回答配置或连续性疑问时，再补故障窗口内的应用记录。字段依据对外 `ax_global_type.h` 的 `AX_AUDIO_FRAME_T`、`ax_comm_aio.h` 的 `AX_AUDIO_STREAM_T` 及相应 API 原型：

| 材料 | 最小记录 |
|---|---|
| 调用摘要 | 时间、run_id、目标 card/dev/chn 或实例标识、API、关键实参、原始返回值、等待参数；失败和停止/重建也要保留 |
| 有效配置 | AEC 模式及活动 union 分支，各处理开关/级别；具体项见 [signal-quality.md](signal-quality.md) 第三节 |
| PCM 帧/音频流 | 成功取得的数据记录 `u32Seq/u64TimeStamp/u32Len/bEof`；PCM 另记 `enBitwidth/enSoundmode`，配对疑问按需加临时帧标识 |
| 可选 getter | 复用应用已有 AI/AO 属性、音量、静音及 codec 读回；增益/滤波入口见 [signal-quality.md](signal-quality.md) 第二节 |

只把成功调用的输出作为有效读数；失败保留返回码，不能把未取得的输出当实际零值。没有现成 getter 工具时补应用日志，不把 C API 名写成可直接执行的 shell 命令。帧记录不要求导出原始内存地址；长度与格式按 [contract.md](contract.md) 解释，时间戳/序号和取还规则见 [delay.md](delay.md)。

## 三、抓取输入、参考和输出

### proc Dump

该版 AI 的三个主要采集点如下。这里的 mic/ref/output 表示测量角色，具体处理阶段必须另行注明。

| 采集点 | 位 / 掩码 | 用途 |
|---|---|---|
| `AI_DUMP_BIT_VQE_IN` | bit 5 / `0x20` | VQE 输入 mic；此前可能已有 codec 增益或前置处理 |
| `AI_DUMP_BIT_VQE_REF` | bit 4 / `0x10` | AEC 实际使用的 ref，优先用于确认参考内容 |
| `AI_DUMP_BIT_VQE_OUT` | bit 3 / `0x08` | VQE 输出；结合 NS/AGC 等开关判断，不能默认视为纯 AEC 输出 |

先保存目标设备原 `Dump/DumpPath/DumpCount/Bypass`，确认没有正在进行的其他采集；选择本轮新目录，检查可用空间，约定帧数和最长采集时间。下面是命令模板，**替换全部尖括号内容后再执行**：

```bash
echo DumpPath "<AiCardId>" "<AiDevId>" "<本轮输出目录>" > /proc/ax_proc/ai
echo DumpCount "<AiCardId>" "<AiDevId>" "<本轮帧数>" > /proc/ax_proc/ai
echo Dump "<AiCardId>" "<AiDevId>" 0x38 > /proc/ax_proc/ai
```

`0x38` 由上述三个公开位相加得到。检查写入结果和新文件后复现；结束或达到时间/空间上限时停止：

```bash
echo Dump "<AiCardId>" "<AiDevId>" 0x0 > /proc/ax_proc/ai
```

确认停止写入后收集文件，恢复原抓取设置并读回。`DumpCount` 单位是**数据帧**，各点帧长可能不同，不能直接当秒或 KB。文件名、覆盖规则、到数后状态及跨重建行为要按实际文件和读数确认；不假定自动停止。记录每步失败，不能把写入命令已发送当作采集成功。

需要找首个异常点时，按该版 §5.5 增加 CODEC、重采样、VOL_CTL 或输出队列的相邻点；AO/AENC/ADEC 分别使用自己的位定义和设备/通道参数。抓取保持原处理配置，Bypass 对照另按 [signal-quality.md](signal-quality.md) 执行。

### SaveFile / QueryFileStatus

已有应用或 Sample 使用保存接口时，核对下表，不必同时开启两套采集：

| 接口或字段 | 约定与判断 |
|---|---|
| `AX_AI_SaveFile` | 需 VQE 已使能；否则保存无效。先查 VQE 条件、API 返回值和路径 |
| `Sin.pcm / Rin.pcm / Sou.pcm` | 分别为 VQE 输入、AEC 参考、VQE 输出，含义对应上表；实际命名以本轮文件为准 |
| `AX_AUDIO_SAVE_FILE_INFO_T` | 保存 `bCfg/aFilePath/aFileName/u32FileSize`；`u32FileSize` 单位为 **KB**，与 DumpCount 分开记录 |
| `AX_AI_QueryFileStatus` 的 `bSaving` | `true` 表示正在保存；启动成功后跟踪结束状态，并核对本轮非空文件及大小。单独 `false` 不能证明成功采到数据 |
| `AX_AO_SaveFile / AX_AO_QueryFileStatus` | 保存同样要求 VQE，配合查询确认状态；输入/输出两类文件用于播放处理前后对照，不能代替 AI 实际 ref |

若故障现场 VQE 未启用，选用匹配的公开 Dump 点；开启 VQE 会改变现场，不能只为获得 SaveFile 文件而开启。Sample 的保存选项及输入格式先核对该版帮助。

### 录音有效性

录音必须注明：

- **来源**：准确采集点及前后处理；Sou 也不必等于最终发送流。AO 播放文件不能直接代替实际 ref。
- **身份和格式**：采集器版本、设备/实例、run_id、采样率、位宽、声道布局、各处理开关及增益。
- **时间关系**：起止时间、采样时钟关系、每路 sample 0 的含义。相同大小或同时打开文件不能证明同步。
- **文件状态**：每轮新文件名、写完状态、大小及哈希；停止/重启对抓取的影响按本版对外说明和实际状态确认。

每种场景可先采 10–20 秒，启停问题覆盖切换前、整个异常过程及恢复后；具体时长按故障窗口决定并设置上限。混合场景标出谁在讲话；切片使用共同时间区间并记录样点偏移，不能分别裁掉各路开头静音。

文件后缀和编辑器轨道显示不决定磁盘格式；核对文件头或采集配置。多声道拆分须有已确认的布局，内部回环的无效声道不能当作 ref。格式转换保留原件与操作记录。

采集会增加 I/O。卡顿或负载问题需对照开/关录音是否改变现象。长时问题保留跨时段片段、累计采放样本数和计数日志，单个短片段不能排除长时变化。

### 对照素材与测量区间

比较修正前后或不同音量时，先约定要验证的语音场景和产品要求。按《AX 音频调试指南》§1.2–1.3（封面 V0.1，修订历史含 2025/12/01 V0.2）的选区电平、频谱查看方法记录观测值，保留以下条件：

| 项目 | 最小记录 |
|---|---|
| 播放素材 | 文件名/哈希、播放区间、是否循环；固定语音及停顿片段，每轮标出近端与远端讲话区间 |
| 产品条件 | 目标播放音量、近端拾音要求；本轮各级增益、处理开关、装配和摆放状态 |
| 声源与测点 | 声源相对 MIC/扬声器的位置、距离和朝向；有声压计时另记仪器、测点及读数，没有则注明未测声压 |
| 分析区间 | 原文件及起止时间/样点、采集点、对应素材片段；跨轮选相同内容和阶段，同轮多路切片沿用共同时间区间 |

通话效果使用包含停顿、弱语音及单双讲的语音片段验证。纯音或扫频用于有明确测量条件的电性能/频响检查；单频结果不能替代语音保真和双讲验收。电性能实验的处理开关另行记录，完成后恢复业务配置。

电平记录区分 **RMS/峰值及其单位**与测点处的 **dB SPL**。工具的 `rms_dbfs/peak_dbfs` 是数字满幅基准下的测量，未标定的 PCM 不能换算为声压；不同采集点的幅值也不能直接作为声学耦合增益。相同音量档位不证明实际响度相同，变更了增益或器件时需重新确认。

测量使用原始电平数据。归一化、增益调整或降噪后的副本只用于注明目的的展示/分析，不能反推原始电平、底噪或削顶情况；裁剪副本保留原始偏移，不能据副本起点推断原始时差。没有共同分析区间时，全文件平均值仅作概况。

现有脚本提供数字 RMS/峰值、分窗 RMS 和满幅样本比例 `rail_fraction`；后者只统计落在整数幅度端点的样本，不能覆盖全部失真。声压、电路或声学失真需要对应测量，阈值采用客户要求或认可基线。

## 四、材料保存与工具输入

采集并保存客户故障现场的配置、日志和原始录音，保留对应设备、复现轮次和时间信息，存放按主流程资料范围执行。需要分享时按客户授权范围提供；涉及私人语音、标识和地址的处理在分享副本上进行，保留原始材料用于分析，不默认上传。

需要测量时由 Agent 按 [contract.md](contract.md) 整理请求。本 skill 不带通用板端采集器；整理已有文件不能写成“已完成板端采集”。
