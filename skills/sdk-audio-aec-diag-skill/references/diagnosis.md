# 配置、参考、启停与问题归属（Phase 2/3/5）

## 一、版本和接口核对

分别记录整套 SDK、编译所用对外头文件的发布包、AI/AO 与处理库版本；proc 版本头只代表对应组件。当前工作区头文件不自动代表客户运行版本。需要换库或构建时，再核对工具链、ABI 和原有构建方法。

本文件依据《AX AUDIO API 文档》V1.7（2026/07/13）§1.2.2、§2、§3、§5，以及对外头文件 `ax_ai_api.h/ax_ao_api.h/ax_audio_process.h` 的相应声明。先确认与客户版本匹配；头文件只声明而未说明的行为，继续按匹配文档确认。

| 目的 | 查阅名称 | 重点 |
|---|---|---|
| 集成 VQE 设置/读回 | AX_AI_SetUpTalkVqeAttr / AX_AI_GetUpTalkVqeAttr | AEC 模式、处理率、帧长及调用阶段 |
| 下行 VQE 设置/读回 | AX_AO_SetDnVqeAttr / AX_AO_GetDnVqeAttr | 下行属性只列 NS/AGC，没有 AEC 配置；不能作为上行 AEC 已开的证据 |
| 设备属性与使能 | AX_AI_SetPubAttr / AX_AI_GetPubAttr / AX_AI_EnableDev | 布局、设备率、位宽、周期及目标设备 |
| 独立处理 | AX_AP_UpTalkVqe_Create / AX_AP_UpTalkVqe_Process / AX_AP_UpTalkVqe_Destroy | mic/ref/out 格式和实例生命周期；不可与 SDK 上行 VQE 同时使用 |

### 设置和读回

集成模式按**设置 AI 设备属性 → 设置 VQE 属性 → 启用设备**核对调用摘要和返回值。同一设备 VQE 属性不支持动态设置，重新设置前须先禁用对应设备。`AX_AI_EnableDev` 对已启用设备也会返回成功，不能据此认定已按新参数重建。

AI 的两个属性 Get 接口返回前次设置或默认配置。它们证明读到的配置，运行状态仍要结合目标设备 proc、旁路/布局及本轮录音确认。客户说“VQE 已开”时先确认上行、下行或独立实例，以及实际设置的目标。

独立接口由调用方提供 mic/ref，不假定自动获得参考、拆声道或重采样。`AX_AP_UpTalkVqe_Create` 返回实例指针，Process/Destroy 返回 `AX_S32`；按各自类型记录结果，不能把 Create 返回地址当整数错误码。输入缓冲大小、别名和生命周期按对应文档确认。

### 模式、活动配置与默认值

对外 `ax_audio_process.h` 的 `AX_AEC_CONFIG_T` 用 union 保存 FLOAT/FIXED 配置：

- **按模式解释**：先读 `enAecMode`，只解释活动的 `stAecFloatCfg` 或 `stAecFixedCfg`。未活动分支的字节值不用于判断配置异常；切换前后记录模式及对应完整配置。
- **核对初始化**：全零 AEC 配置对应 DISABLE。注释默认值不等于 C 清零后的值，例如 FIXED 的 routing 注释默认 3，而清零得到 0；不能假定 SDK 自动补齐，需查实际实参与读回。
- **区分枚举与能力**：头文件列出三种 AGC 模式，但上述 API 文档 §3 `AX_AGC_MODE_E/AX_AGC_CONFIG_T` 明确该版仅支持 `AX_AGC_MODE_FIXED_DIGITAL`。AGC 已开且清零后仍为模式 0 时优先核对。客户版本不同则补其对外支持说明，不因枚举存在就建议使用。

各处理开关、级别与双讲判据见 [signal-quality.md](signal-quality.md) 第三节。

### 采样率、格式和帧长

- 该版 TalkVQE 为 **8/16 kHz、16-bit、单声道**，MIC/REF 对应帧长须一致。`ax_comm_aio.h` 的通用采样率枚举不扩大此算法能力；物理采集 `ChnCnt=2` 与算法单声道不是同一层面的要求。
- 分别记录设备率、VQE 处理率和输出率；集成路径支持设备率到算法率的重采样，设备为 48 kHz 不单独证明配置错误。
- `u32FrameSamples` 建议取算法率下 10 ms，如 16 kHz/160、8 kHz/80；这些是推荐值，不能写成唯一合法帧长。VQE 输入长度须为它的整数倍；跨重采样时不能直接用设备周期样本数判断。
- 设备支持 24/32-bit 透传不表示 TalkVQE 支持这些格式。该版 24-bit 数据使用 32-bit 容器；转换前核对布局和有效位，不能按 packed S24 直接读取。
- 区分 samples、bytes、channels，帧时长用 samples / 该阶段采样率计算。位宽、声道、设备周期及重采样方向按 [contract.md](contract.md) 的字段映射核对，不把示例数字当通用枚举值。

## 二、配置和参考判据

### 先选目标设备，再看状态

`analyze.py` 检查请求中填写的配置；Agent 根据同一设备/轮次的 proc 和录音做以下判断，不把其他设备的行用于本次结论。

| proc 信息 | 核对内容 |
|---|---|
| 设备属性 | `ChnCnt/Samplerate/PeriodSize/PeriodCount/LayoutMode/enBitwidth/LinkMode/AiDepth`，与配置、接线和取帧方式对应 |
| VQE 属性 | `VqeEnabled/SampleRate/FrameSamples/AecMode`；该版 AEC 模式 0=DISABLE、1=FLOAT、2=FIXED |
| 处理与音量 | `NsEnable/NsAdvEnable/AgcEnable/VadEnable/SupOrRouting/VqeVolume`；按本版实际输出取值，完整配置及增益判据见 [signal-quality.md](signal-quality.md) |
| FIR / SEC RES INFO | `ResEnable/InRate/OutRate/ResLen/Channels`，确认实际重采样阶段和输出率 |
| 旁路与采集 | `Bypass/Dump/DumpPath/DumpCount`；抓取配置需与本轮文件对应 |
| AO 播放状态 | `InsertSilence/CurrVqeVolume/MuteEnable/Fade`，结合播放时刻解释参考和音量变化 |

`VqeEnabled=1` 只说明 VQE 状态，AEC 还需核对模式；`AecMode!=0` 也要排除 VQE 旁路和布局绕过。Bypass 的具体含义见 [signal-quality.md](signal-quality.md) 第三节。字段拼写差异保留原文，归一化时注明出处。

### 布局与实际参考

布局依据 §3 `AX_AI_LAYOUT_MODE_E/AX_AI_ATTR_T`；对照板级说明和分声道单讲，不能仅凭“内置/外置 codec”选择一个固定值。

| 布局 | 该版含义 | 诊断重点 |
|---|---|---|
| `AX_AI_MIC_MIC`（0） | 左右均 MIC，绕过 HPF/AEC/NS/AGC，直接送 VolCtl，输出交织数据 | “模式已开却无效果”先排除此布局；切换前确认硬件参考来源 |
| `AX_AI_MIC_REF`（1） | 左 MIC、右 REF | 检查声道反接、把第二只 MIC 当 REF |
| `AX_AI_REF_MIC`（2） | 左 REF、右 MIC | 同上，结合实际信号确认 |
| `AX_AI_INTERNAL_MIC_NULL`（3） | 内部回环，左 MIC、右无效 | 实际参考看 VQE_REF/Rin，无效声道全零不等于参考缺失 |
| `AX_AI_INTERNAL_NULL_MIC`（4） | 内部回环，左无效、右 MIC | 同上，MIC 所在声道不同 |
| `AX_AI_DOORBELL/AX_AI_MIC_MIC_DEAL/AX_AI_DATA_ALL` | 另有布局和 buffer 要求 | 查匹配定义，不能自动套用普通双声道拆分 |

### 观察与判断

| 观察 | 可以确认 | 修正或验证 | 反证 |
|---|---|---|---|
| 要求开启，目标设备 AEC 模式关闭或 VQE 被旁路 | 状态不符，归属待查 | 核对设置过程和后续覆盖，保存旧值后修正 | 状态符合预期仍有回声，继续查参考 |
| 布局与已确认接线/来源不符 | 布局不匹配 | 保存旧值，修正对应关系 | 布局正确但 ref 缺失，查播放与路由 |
| 率/格式/帧长超出本版对外说明 | 配置组合不受支持 | 改为受支持组合，核对返回值、状态与录音 | 合法重采样或非推荐帧长不直接算错误 |
| 设置失败或选错设备/实例 | 所需配置未在目标生效 | 核对调用阶段、编号和返回值 | 设置成功且目标正确，查后续链路 |
| 确有播放，实际 ref 全零 | 该段参考缺失 | 先确认采集点，再查静音、源选择和回环 | 抓错点或播放本来静音，不能确认参考缺失 |
| ref 非零但内容不符 | 错流、漏混音或失真待区分 | 分路播放，对照 ref 与 mic | 弱信号、双讲、多径和搜索范围也会导致低相关 |
| mic/output 字节一致 | 采集来源或旁路需核对 | 查同一采集点、文件覆盖和轮次 | 特定输入下相同不能单独证明 AEC 无效 |

参考来自 codec 回环、外部回环还是应用提供，按板级说明和分声道单讲录音确认；只有“多种模式都无效”不能指定声道或认定算法失效。参考内容不符时，按 [signal-quality.md](signal-quality.md) 分路检查。

### 返回码分诊

依据对外 `ax_global_type.h` 的 `AX_DEF_ERR/AX_MOD_ID_E/AX_ERR_CODE_E` 及各音频头文件的错误宏。先保留失败 API、目标、时间、实参和原始返回值；只有确认采用该 SDK 编码的 32-bit 返回值，才按 `u = ret & 0xffffffff` 还原位模式。固定高字节为 `0x80`，其后依次是 8-bit 模块、子模块和错误号；`errno` 或其他库的负数另行解释。

本次核对的模块号为 AI=`0x20`、AO=`0x21`、AENC=`0x0c`、ADEC=`0x0f`、ACODEC=`0x1f`；**VQE 错误使用 AUDIO=`0x1a`**。这里的 AI/AO/VQE/ACODEC 错误宏子模块为 `0x02`，AENC/ADEC 为 `0x01`。例如按公开宏计算，`0x8020020a` 对应 `AX_ERR_AI_ILLEGAL_PARAM`，`0x801a0214` 对应 `AX_ERR_VQE_NOT_SUPPORT`；使用前仍须匹配客户版宏。

| 已匹配的错误类别 | 下一步核对 |
|---|---|
| `ILLEGAL_PARAM / INVALID_CHNID / NULL_PTR` | 查实参、枚举、目标编号和空指针；设置代码存在不等于调用成功 |
| `NOT_SUPPORT` | 查客户平台和版本支持的能力组合 |
| `NOT_PERM` | 查当前调用状态和阶段；不直接解释成 Linux 用户权限不足 |
| `EXIST / UNEXIST` | 查创建、销毁、重复调用和目标实例 |
| `NOMEM / NOBUF` | 通用定义分别指堆内存分配、池缓冲获取失败；分开采集资源与取还记录，见 [delay.md](delay.md) |
| `BUF_EMPTY / BUF_FULL` | 结合等待方式、前后计数和时间线判断；具体队列和触发条件按模块说明确认 |
| `SYS_NOTREADY` | 查初始化、依赖就绪情况和首个失败，不单凭此码指定缺失驱动 |

只认匹配版本实际定义的符号，不为所有模块机械组合通用错误名。未匹配项保留原码并补对外说明；错误类别提供排查方向，不能独自确认客户责任或 SDK 根因。现有脚本仅索引日志候选，符号查找与解释由 Agent 完成。

## 三、切换、重建或唤醒后异常

记录正常通话、停止/重配、重新启用、开始播放、MIC/REF 首次有效和效果恢复的时间，保留每步返回值与前后读回。采集范围、轮次及文件有效性按 [collection.md](collection.md) 确认。

| 方向 | 区分证据 | 验证与反证 |
|---|---|---|
| 配置未恢复或被覆盖 | AEC、布局、Bypass、ALC/各级增益，调用阶段和返回值 | 按第一节流程恢复；配置一致仍异常，查运行状态和实际输入 |
| 播放控制改变 | AO 暂停/恢复、清缓存、静音/淡入淡出的时刻和返回值 | 按 [delay.md](delay.md) 与参考零段或时差突变对照，区分业务事件与异常断流 |
| MIC/参考开始时间不同 | 播放时刻、首个有效 mic/ref | 按公开流程检查启动；参考已连续有效仍异常，不能只归因开始晚 |
| 补偿不合适 | 实际参数、单位、含义和同步录音 | 按 [delay.md](delay.md) 对照；含义不清先补资料 |
| 重建后反复恢复 | 调用摘要、重建时刻和恢复曲线 | 业务允许时对照减少重建；持续采集也异常，继续查其他原因 |
| 录音停止、覆盖或混入旧文件 | 大小、哈希、时间及写入状态 | 换新文件确认录制有效；相同哈希不能单独证明 AEC 未工作 |

复测保留原切换步骤、冷启动、产品负载和恢复时间，再按主流程完成通话场景。减少重建或临时静音的实验，最终仍需满足产品启停要求。

### 播放或解码输入异常时

对外 `ax_adec_api.h` 的 `AX_ADEC_MODE_E` 注释要求 PACK 输入为完整编码帧，STREAM 用于无法确定完整包边界的输入。若播放或 ref 零段伴随解码错误，先采 `enMode`、输入边界、送流返回值、EOF 和解码输出，区分：

- `AX_ERR_ADEC_BUF_LACK`：输入不足以解出一帧，先查组包和输入连续性。
- `AX_ERR_ADEC_END_OF_STREAM`：流结束，结合业务结束事件判断是否符合预期。
- `AX_ERR_ADEC_DECODER_ERR`：解码错误，核对编码格式、输入及匹配公开说明。

传输分片不能直接当完整解码包。改 STREAM 前须确认本版及对应编码格式支持；输出恢复后再验证实际 ref 和 AEC，不能把模式切换当通用修复。

### 需要最小对照或硬件分诊时

依据《AX 音频调试指南》§2.2、§2.9、§2.10（封面 V0.1，修订历史含 2025/12/01 V0.2）及《AX 外围设备驱动开发指南》V0.5（2026/05/15）§10。硬件示例先核对板型，不将其他芯片例子套为 AX615 固定配置。

公开 Sample 对照：先确认本版帮助中的 `sample_audio ai/ao` 及 `-D/-d/-r/-p/--aec-mode/--routing-mode/--layout/--save-file`。在可中断业务的窗口释放原应用设备，用同板、同素材、同音量、同接线运行 Sample，保存 proc 和录音；布局和设备号取本板实际值。Sample 正常则比对应用与 Sample 的配置、调用阶段和参考路线；同样异常则继续查输入、参考与板级条件。离线 `sample_audio up_vqe` 先确认 mic/ref 格式、选项和独立接口互斥条件。

| 现象 | 分诊动作 |
|---|---|
| `pcm_open` 阻塞 | 查上一实例关闭与声卡 fd 释放，停止反复启动采集进程 |
| 声卡使能失败 | 区分驱动内建或 KO；`lsmod` 无条目不证明内建驱动缺失。需要加载时再按匹配文档核对依赖 |
| mic/ref 缺失 | 核对内置/外置/混用 codec、MIC 类型及本板 DTS 的 `status/widgets/routing`，再对照实际 I2S 接线和参考来源 |
| 外置 codec/回环异常 | 按原理图核查 I2C 控制和 I2S 时钟；需要硬件测量时由板级人员在播放期间检查 `IIS_MCLK/IIS_SCLK/IIS_LRCK` |
| 只有启停爆音或 PA 开关噪声 | 转采放启停/硬件方向，单独保存触发窗口，不直接套持续回声判据 |

## 四、换版本后退化

1. **确认部署**：核对实际文件与成套发布清单，版本和 ABI 按第一节确认。
2. **核对差异**：比较配置、参考路线和各版对外要求，排除录音错配、参考缺失、严重失真及明显断流，未排除项保留。
3. **重复对照**：同板、同素材、同音量及声学条件比较正常/异常版本；独立接口允许时可重放同一授权输入。
4. **保存结果**：记录必要差异、前后录音、失败次数/试验次数及回退方法；缺少对照版本或录音时注明未完成。

回归保留原负载、切换或长时条件，按原复现频率记录运行时长和重复次数。差异可重复且配置/环境证据不能解释时，按下一节判断 SDK 嫌疑，不能凭相似症状指定历史缺陷。

## 五、客户使用问题还是 SDK 问题

| 证据 | 结论 | 还需做什么 |
|---|---|---|
| 实际设置/调用违反该版对外约定，有本次读回或返回值证明 | 已确认配置或使用不符合约定 | 指出约定与差异，修正后验证是否解释原症状 |
| 配置文件正确但读回不同，设置过程未查清 | 配置状态异常，归属待定 | 查设置结果、目标实例、后续覆盖和首次变化 |
| 实际 ref 缺失、错流或失真，上游证据不全 | 参考或信号异常，归属待定 | 对照允许采集的处理点，缩小异常范围 |
| 用法符合对外说明、输入有效、录音可信，异常仍可重复 | 疑似 SDK 问题 | 给最小复现；可用时补公开 Sample 或成套版本对照 |
| 只有相似现象、单个错误码或脚本候选 | 信息不足 | 补最能区分解释的一项证据 |

Sample 正常或同样失败都要核对版本、输入、配置、参考路线和板级条件，不能直接判定客户 APP 或 SDK 有错。正式缺陷与修复版本以供应商允许对外交付的说明为准。
