# 时延、补偿与时间连续性（Phase 3）

## 一、测量前提

| 检查项 | 要求 |
|---|---|
| 场景 | 远端单讲有实际标记，双讲/近端单讲不做本项测量 |
| 时间 | 同次复现、共同采样时钟、sample 0 对应同一时刻 |
| 格式 | 同采样率、同长度、mono S16_LE 或 16-bit WAV |
| 位置 | 补偿前，或补偿后且 AEC 前；AEC output 不能代替 mic |
| 其他补偿 | 记录已有软件/硬件偏移，不能重复计算 |

文件名、相同大小或同时写文件不能证明以上条件。不要先对齐波形再解释原始时差；切片需共同时间区间及原始样点偏移。

运行与 `delay` 输入字段见 [contract.md](contract.md)。测量需要至少三个不重叠窗口和两侧搜索余量，工具默认参数下至少 4 s；启动突变按共同区间分段分析。

## 二、结果解释

定义 `mic[n+d]` 与 `ref[n]` 匹配，则 lag=d：正值为 mic 晚，负值为 mic 早；毫秒值为 d/sample_rate×1000。反相按绝对相关峰搜索，同时保留相关系数符号。

| 状态 | 可解释的范围 |
|---|---|
| estimated | 声明的前提满足且各窗一致，给出 lag_samples/lag_ms，仍需效果验证 |
| provisional | 峰值一致但场景/起点/轮次未确认，仅解释 file_relative_median_ms，不能换算板端补偿 |
| inconclusive / unavailable | 信号、资料或依赖不足，按拒绝原因补采或修正输入 |
| unstable | 有效窗口时差不一致，查丢帧、切换、时钟或路径变化，不能直接认定漂移 |

先看各窗区间、峰值、竞争峰和接受/拒绝原因。边界峰需扩大搜索范围或补采；静音、多峰、削顶等可能使测量无法确定。工具筛选阈值不是质量标准或统计置信区间；多径下最强路径不保证最早到达，采样分辨率不代表总误差。

## 三、补偿参数怎么比较

必须取得参数实际值、单位、读回出处、该版本对外定义和采集位置。只有参数明确表示**同一路 ref 的总纯延迟，增加参数会等量延迟 ref**，且其他偏移已核算，才能使用自动比较。

《AX AUDIO API 文档》V1.7（2026/07/13）§3 `AX_AP_UPTALKVQE_ATTR_T` 将 `s16InSndCardBufMs` 定义为声音从播放到采集的延迟，单位 ms。可据此索取实际设置值，但该定义未说明参数增加会等量延迟 ref，也未给出这里可用的范围、默认或自动模式。因此不能仅凭名称/单位将其填为 `semantics=total_ref_delay`；未知含义时按 [contract.md](contract.md) 仅记录实际值和出处。

缓存分量、附加 offset、自动模式、含义未知或实际值为负时，不做总延迟自动比较；工具返回 not_comparable，按契约保留实际值和出处。

| 采集点 | 总延迟候选 |
|---|---|
| 补偿前 | mic 比 ref 晚 d ms，则候选为 d；当前值明显超过时提示 configured_too_large_candidate |
| 补偿后且 AEC 前 | 当前总延迟 P、残余时差 r，则候选为 P+r；稳定负 r 是过补偿线索 |

先排除 MIC/REF 反接和文件起点偏移，不能把负 r 直接写入非负参数。工具仅在差值超过“认可容差、跨窗极差、一采样分辨率”三者最大值时提示，不自动改板端设置。

修正前核对允许范围和默认/自动模式，按主流程比较启动与稳态录音、残余回声和近端保真。“回声持续几秒”不能换成要设置的延迟。

## 四、时差变化、断流与长时问题

把同次复现的事件、录音与计数放在共同时间线上。单张快照只代表当时状态，变化需要前后证据。

### 用哪些计数缩小范围

以下字段来自《AX AUDIO API 文档》V1.7 §5.1–5.4。先按目标设备/通道选同一实例的前后快照，计算增量，保留重建、复位和回绕情况；由 Agent 判读，现有工具不自动做计数差分。

| 模块 | 计数 | 对照方向 |
|---|---|---|
| AI | `GetBlockFail/Readi/FifoFull/DispatchFail/GetFrm/RlsFrm` | 取块、采集、输出队列和取还帧的变化 |
| AO | `SndFrm/GetFrm/Writei` | 送入、取出和写声卡是否持续推进 |
| AENC | `SndFrm/RecvFrm/EncOk/BufFull/GetStrm/RlsStrm` | VQE 输出正常而发送异常时，查编码及取流 |
| ADEC | `SndStrm/DecOk/BufFull/GetFrm/RlsFrm` | 播放或参考中断时，查解码输入及输出 |

不同计数可能处于不同阶段或使用不同帧粒度，数值不相等不能直接推出丢帧。错误增量要与异常时刻对应，历史非零不单独定因。

### 帧记录与取还配对

按 [collection.md](collection.md) 补应用调用记录。对外 `ax_global_type.h/ax_comm_aio.h` 声明了帧/流的时间戳、序号、长度和 EOF，但未说明时间戳单位、时钟域及重置规则；确认前不能直接换算毫秒或跨模块相减。序号跳变先对照重建、复位、结束及记录缺口；stream 的“无有效帧时序号为 0”注释不能套用到 PCM frame。

以下取还要求依据《AX AUDIO API 文档》V1.7 §2.1、§2.3、§2.4，按匹配版本确认：

| 取 / 还接口 | 核对重点 |
|---|---|
| `AX_AI_GetFrame / AX_AI_ReleaseFrame` | 非 Link 模式、目标设备已启用；同一声卡/设备成功取帧后配对及时释放 |
| `AX_AENC_GetStream / AX_AENC_ReleaseStream` | 同一通道配对及时释放，保留取流返回的原始结构信息 |
| `AX_ADEC_GetFrame / AX_ADEC_ReleaseFrame` | 非 Link 模式主动取帧，同一通道配对及时释放 |

只对成功获取的帧/流核对释放结果，结合采集窗口边界和仍在处理的对象判断；Get/Release 计数暂时不等不能独自证明泄漏。头文件中的接口声明不能证明任意 Link 模式都可主动取帧。

该版 `AX_AI_GetFrame/AX_AENC_GetStream` 的 `s32MilliSec` 为 -1 无限等待、0 非阻塞、正数按毫秒等待；`AX_ADEC_GetFrame` 使用 `bBlock`，不能照搬这套数值。超时或空缓冲需结合实际等待参数、输入推进和本轮频次解释，其他 API 的等待约定逐项查文档。

### 静音与队列状态

该版 §2.2、§3 `AX_AO_ATTR_T/AX_AO_DEV_STATE_T` 说明：AO `InsertSilence` 开启时，FIFO 无数据会填充静音；关闭时无数据会停止硬件播放。参考零段需对照实际播放、送帧、静音/淡入淡出状态，区分业务停顿和异常断流。

对外 `ax_ao_api.h` 提供 `AX_AO_ClearDevBuf/AX_AO_PauseRecvFrame/AX_AO_ResumeRecvFrame` 及 `AX_AO_SetVqeMute/AX_AO_GetVqeMute`。把这些调用、播放率/音量切换与混音变化放到同一时间线，保留目标、时刻、参数和返回值，再对照参考零段或时差突跳。接口名称不能证明静音是否同步作用于实际 ref。

静音读回同时保留 `bEnable` 和 `AX_AUDIO_FADE_T` 的 `bFade/enFadeInRate/enFadeOutRate`。`ax_comm_aio.h` 的 fade rate 枚举列出 32–1024 中的离散值，未给出持续时间单位，不能直接当作毫秒；效果以本轮录音与匹配说明核对。

`AX_AO_QueryDevStat` 应在通道启用后查询；保留 `u32DevTotalNum/u32DevFreeNum/u32DevBusyNum` 的前后值。`longPcmBufDelay` 是声卡 PCM 缓冲的帧延迟，仅非填充静音模式下可用于判断播放完成。保留原单位和适用条件，不把该值当毫秒或完整声学时延。

### 按变化形态判断

| 现象 | 所需证据 | 判断与验证 |
|---|---|---|
| 时差固定 | 多段有效测量、共同起点、补偿位置 | 核对补偿；固定偏移不等于时钟漂移 |
| 时差突跳 | 帧号/时间戳、丢补帧、切换/重建和负载事件 | 重复触发，先找跳变原因，不能用固定参数掩盖 |
| 时差逐渐变化 | 跨时段可靠窗口、累计采放样本数、队列/时钟记录 | 排除积压、丢补帧、重采样和路径变化，再提出时钟候选 |
| 零段、重复波形或突变 | 播放内容、帧号、日志和录音状态 | 先排除自然静音、周期素材和采集丢数据 |
| xrun/超时/错误计数 | 前后快照、计数定义、重启/回绕记录 | 计算本次增量并关联症状，历史非零值不能直接定因 |
| 高负载恶化 | CPU/存储负载、公开 API 耗时、参考连续性 | 对照负载及录音 I/O，不能据耗时猜内部锁或线程 |

`delay.py` 只比较首、中、尾等最多五个窗口，没有自动长时 ppm 拟合或完整逐帧关联；`unstable` 不代表已定位漂移。启停配置恢复和版本对照见 [diagnosis.md](diagnosis.md)。复测须覆盖原负载或长时条件，记录运行时长和重复次数。
