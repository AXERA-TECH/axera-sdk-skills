# AX615 Audio AEC 故障诊断助手

入口见 [SKILL.md](SKILL.md)。客户可直接描述问题，或提供一键采集包、配置、日志和录音；Agent 按证据逐步排查。

> 使用 sdk-audio-aec-diag-skill 分析：切换对讲后远端听到回声，过一会儿恢复。这是采集包。

普通诊断无需 Python。音频测量需 Python 3.10+，时延另需 NumPy，操作见 [工具使用与格式](references/contract.md)。

## 安装

在本目录执行：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 scripts/install.py --out ../aec-skill-bundle
```

安装器生成运行资源和 SHA256 清单，排除测试、评测答案和仓库元数据。输出目录须尚不存在。

## 评测材料

本交付包保留用例输入、答案和独立断言，不提供原内部自动评测工作流。评测方需隔离输入与答案，单独记录本次运行结果；用例存在不代表模型评测或板端声学验证已经通过。

`evals/` 保留 5 个现场诊断场景：AEC 未启用、实际参考缺失、稳定时延与配置不匹配、MIC 输入削顶伴随残留回声、双讲吞音。按常见排查方向选取，不代表客户工单频次统计。

| 用例 ID | 场景 |
|---|---|
| axaudioaec-001 | AEC 未启用 |
| axaudioaec-002 | 实际参考信号缺失 |
| axaudioaec-003 | 稳定时延与配置不匹配 |
| axaudioaec-004 | MIC 输入削顶伴随残留回声 |
| axaudioaec-005 | 双讲断续与首字丢失 |

```text
evals/cases/axaudioaec-001/
├── fixtures/               # 分析器可见的现场材料
│   ├── proc.txt
│   ├── capture.txt
│   ├── application.log  # 仅有操作记录的用例提供
│   └── AiCard0_Dev0_*.pcm
├── answer/              # 仅评分方可读
│   ├── case.yaml        # 元数据、输入哈希、复现状态和可见性声明
│   ├── oracle.yaml      # 完整事实、必答项、允许未知、补证据及语义审阅规则
│   ├── reproducer.patch # 当前为不可用说明，不含可执行补丁
│   └── assert.sh        # 确定性测量、结构及部分文本 smoke 检查
├── assert.sh            # 自动生成的单文件 Harness 入口：评分规则 + 报告校验
└── case.yaml            # 平台 Harness 的任务契约
```

每个 `fixtures/` 提供 AI/AO `proc.txt`、`capture.txt` 及 MIC、REF、处理后输出三路 PCM；AEC 未启用和时延配置场景另有 `application.log`。时延配置场景另提供应用配置快照 `fixtures/config.txt`；削顶场景仅提供故障轮次的三路录音，增益对照作为后续验证步骤。各用例只提供故障轮次，修正后验证由报告提出。现场说明仅记录听感、格式、采集操作和文件清单；状态与参数由原始日志或配置快照提供，不在说明或 prompt 中突出某个处理开关、参数或排查方向。材料不足时评分接受有证据的候选判断，并要求补证，不以隐藏答案要求确定归因。材料的完整性和缺失的日志等级证明等记录在 `answer/case.yaml`；不补造采集记录或故障注入补丁。`answer/oracle.yaml` 定义黄金答案的语义边界；`answer/assert.sh` 提供确定性自动检查，两者职责不同。

分析时只将 `fixtures/` 内容复制到仓库外的新工作目录，由评测方提取根目录 `case.yaml` 的 `prompt` 交给分析器；`answer/` 和任务中的期望结果不进入分析工作区。分析器从现场材料整理测量输入，生成 `out/measurements.json`、`out/measurements.md`、`out/diagnosis.json` 和 `out/diagnosis.md`。

元数据逐文件声明输入和技能运行资源白名单，并将答案及断言列为评测专用材料。评测前核对输入哈希、材料可见范围和日志证据锚点；未知板型及 SDK 版本保持未知。

003 使用仓库 001 的 REF 前 8 秒语音，生成固定时差录音和配置，未使用客户私有材料。生成程序未随本交付包提供，当前包不提供自动重建命令。该材料不模拟 SDK AEC 算法，也不代表板端修正验收。当前用例未提供硬件基线或故障注入 diff；五份 `reproducer.patch` 明确记录 unavailable，不可用于 `git apply`，板端状态为 not_run。

分析完成后，由评测方在隔离环境中执行独立断言与报告校验，结果记录在本次评测输出目录。排查失败时查看汇总报告和对应样本的 `result.json`、`assert.log`（若已执行断言）及已生成的输出文件。所有关键断言逐项通过才算通过，多次运行分别保留结果，不采用多数票。黄金答案另按 oracle 的结论、证据归属、推理边界、措施与反证、回归五个维度审阅：允许同义表述；否定、引用和待验证假设不作为肯定根因判负；输入缺失的信息允许未知。当前文本正则只提供 smoke 检查，不能判定完整语义正确，也不启用模型自评。自动断言通过不等于黄金答案语义审阅、真实硬件复现或声学验收通过；解决率只统计客户确认且有复测证据的问题。

## 发布检查

发布前按 [SKILL.md](SKILL.md) 的资料范围核对资源，确认不包含凭据和未获授权的客户材料。输入日志、音频来源和非文本资源需分别审核；文件扫描不能替代内容与资料公开依据的核对。

技能内的 `scripts/install.py` 只生成运行资源和 SHA256 清单；仓库根目录统一安装入口则复制所选技能目录，可能包含评测材料。开展盲测时应使用隔离的运行资源，评测方单独持有答案。

工作树检查通过不代表既有 Git 历史可以公开。
