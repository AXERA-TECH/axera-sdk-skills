# Platform: m57

M57 是 Axera 的 SoC 架构层。`AX637` / `AX637R` 属于 M57 架构的子平台：启动链路、构建框架、内存与分区机制、BOOTROM 方案、BootCnt 与 OTA 均复用本文件描述；仅在 board/SDK 层存在差异，见 `platforms/ax637.md`（通过 `extends: m57` 自动叠加）。

事实来源：`reference/m57/00 - AX SDK 使用说明.md`、`reference/m57/M57 SBL启动特性介绍.md`。

## 目标平台配置与公共构建规则

- 查看当前 SDK 支持的平台：`make plist`。
- PLAT 命名规则为 `BOARDNAME_FLASHTYPE`。
  - M57：`BOARDNAME` = `demo` / `evb`；`FLASHTYPE` = `nor_emmc` / `nor_nand` / `only_nand`。
    - `nor_nand`：Safety 镜像放 NOR，Main 镜像放 NAND。
    - `nor_emmc`：Safety 镜像放 NOR，Main 镜像放 eMMC。
- 平台配置目录：`build/platforms/axera/<PLAT>/`，含 `config.mk` 与 `partitions.json`。
- 全量编译：`make PLAT=<PLAT> clean all install axp`。
- 组件单独编译（分别进入 `boot/atf`、`boot/optee`、`boot/uboot`、`kernel/linux`、`rootfs`）：`make PLAT=<PLAT> clean all install`。
- 版本：U-Boot `u-boot-2022.10`；Kernel `linux-6.1.83`。
- U-Boot defconfig 示例：`m57-demo-nor-nand_defconfig`；Kernel defconfig 示例：`m57-tiny_defconfig`（`kernel/linux/linux-6.1.83/arch/arm64/configs`）。
- DTS 目录：`kernel/linux/linux-6.1.83/arch/arm64/boot/dts/axera/`。
- 关闭 OP-TEE：在 `build/platforms/<PLAT>/config.mk` 中设置 `SUPPORT_OPTEE := FALSE`。

## 启动链路（M57 架构）

| 阶段 | 执行者 | 关键动作 | 交付物 |
| --- | --- | --- | --- |
| 加载 | R5F BootROM | 初始化 Safety 域（power/clock/OCM）；从 NOR/NAND/eMMC/HyperFlash 加载 SBL 到 Safety OCM，解密并验签 | SBL |
| Safety | SBL | 初始化 Main 域硬件；加载 A55 SPL 到 Main OCM，验签后触发 A55 执行 SPL | SPL |
| Main | SPL | 配置必要硬件（power/clk/reset/pinctrl 等）；加载 BL31/OP-TEE/U-Boot 到 DDR，交权 BL31 | BL31 |
| EL3 | BL31 | 初始化 EL3/MMU/PSCI/GIC/SPD；ERET 跳 OP-TEE | OP-TEE |
| EL1 secure | OP-TEE | 初始化 EL1 secure/UART/MMU/GIC/thread；SMC 回 BL31，BL31 就绪后 ERET 交 U-Boot | U-Boot |
| EL2 | U-Boot | 初始化 EL2/C 运行环境/UART；加载 eMMC/Flash 驱动与 env；从 eMMC/flash 加载 Kernel+dtb 验签 | Kernel |
| OS | Kernel | 挂载 rootfs，完成 OS 初始化 | — |

## U-Boot 目录结构

`boot/uboot/` 下包含顶层 `Makefile`（Axera 平台编译与打包）和 `u-boot-2022.10/`（改自开源版本，含 `api/ arch/ board/ cmd/ common/ configs/ disk/ doc/ drivers/ dts/ env/ examples/ fs/ include/ lib/ net/ scripts/ test/ tools/ .config`）。

## U-Boot 引导内核方式（默认）

默认走 `distro_bootcmd`（引导方式可在 `menuconfig` 中修改）。调用链：

```
bootcmd=run distro_bootcmd
  -> bootcmd_blk_extlinux -> boot_extlinux
  -> sysboot ${devtype} ${devnum}:${distro_bootpart} any ${scriptaddr} ${prefix}${boot_syslinux_conf}
```

`sysboot` 核心：探测分区文件系统 → 读取 `extlinux/extlinux.conf` → 按配置把 kernel 加载到 `${kernel_addr_r}`、设备树加载到 `${fdt_addr_r}`，再按镜像格式决定调用 `booti` 还是 `bootm`。

`extlinux/extlinux.conf` 示例：

```
default m57_base
menu title Axera Boot Options
prompt 0
timeout 0
label m57_base
kernel /Image.axgzip
fdt /m57-demo-nor-nand.dtb
```

关键环境变量：`devnum=0`、`devtype=mtd`、`distro_bootpart=9`、`prefix=/`、`boot_syslinux_conf=extlinux/extlinux.conf`、`scriptaddr=0x10f000000`、`kernel_addr_r=0x110000000`、`fdt_addr_r=0x118000000`、`boot_targets=blk_extlinux tftp dhcpboot`。

## 内存规划

- 默认 DDR 为 1 GiB。
- Linux 使用的最大内存为 384 MiB；作为大段物理连续内存管理的 CMM 为 640 MiB。
- Linux 内存内部还需为 ATF、OP-TEE 等固件预留空间。
- 静态调整（以 `demo_nor_nand` 为例）：修改 `build/platforms/axera/demo_nor_nand/config.mk` 中的 `SYSTEM_MEMORY_SZ` 与 `LINUX_MEMORY_SZ`，两者之差即 CMM 大小；若 `config.mk` 无这两项需自行添加。
- 动态调整：运行到 U-Boot 命令行后修改 `SYSTEM_MEMORY_SZ` / `LINUX_MEMORY_SZ`。
- Inline ECC：跟随 fusa 开关，普通版本默认关闭、fusa 版本默认开启。Linux 内核空间那段不可改；CMM ECC 空间需跟随 DDR 大小适配，修改 `SafetyIsland/driver/ddr/ddrmc_init.h` 的 `INLINE_ECC_BLOCK_1_START` 为 `DDR大小 - 128M`。`DDR大小-128M` 到 `DDR大小` 为 ECC code 存储区，软硬件均不得使用。

## FLASH 存储空间分配与分区

- 分区表位于 `build/platforms/axera/<PLAT>/partitions.json`，分区的先后顺序在代码中固化，通常只需关注各分区 `size`。
- 该文件经脚本解析为 `mtdparts` 格式字符串，由 axdl 写入 metadata 分区，U-Boot 启动后读取。
- `size` 单位为 KB，且必须是 erase/block size 的整数倍：NOR 为 4K（GD25F64），NAND 为 256K（W35N04JW）。
- 调整分区大小：只改 `partitions.json` 对应 `size`，其余脚本自动适配。
- 新建/删除分区：M57 文档明确“暂不支持创建和删除分区，以免影响设备启动”。

## 引导 RTOS 镜像（OCM + DDR）

- RTOS 镜像默认加载到 OCM；当 RTOS 镜像 header 中 `ddr_bin_offset != 0` 时，镜像被 offset 拆为 OCM 段与 DDR 段。
- `ddr_bin_offset == 0`：只映射 4M DDR，先放 NPU OCM 再解到 OCM。
- `ddr_bin_offset != 0`：除映射 4M DDR 外还映射 10M DDR 用于 load；10M DDR 中 4M 用于 gzip，先放到该 4M DDR 再解到开头 6M DDR；`[ddr_bin_offset, img_size]` 段搬到 4M DDR 地址开头。
- 常见失败原因：
  1. ddr bin 未成功打进 RTOS img，或 `header->ddr_bin_offset = 0`。客户工具链不一定是 SDK 的 armclang，需参考 SDK 的方案声明 section 生成带 ddr bin 的 img，并更新 `header->ddr_bin_offset`。
  2. 放 DDR 上的 bin 默认只支持 4M。超出需：调整 `SDK/SafetyIsland/board/include/sbl/sbl_demo.h` 中各 remap DDR 区域映射；按扩大需求调整 AUTOSAR 链接脚本中的 DDR 内存布局；对新预留 DDR 空间在 Linux DTS 中设置 `reserved`。

## SBL AB 管理

- ROMCode 先按 reset-retained register（`SW_DATA0`）选择第一级 boot 镜像的 slot；SBL 再读取介质中的 Android AB metadata 判断持久状态应启动的 slot。两者不一致时，SBL 通过 `safety_abc_setup()` 更新 `SW_DATA0` 并触发 WDT reboot，让下一轮 ROMCode 从正确 slot 起。
- ROM 选 slot：读 `SW_DATA0`；若 `BOOT_STAT=1` 认为上一轮未完成 → 切另一 slot → 递增 `BOOT_ERR_TIMES`；失败次数 `>1` 则停止自动切换、进入 download/sdboot 恢复路径；仍可尝试则 `BOOT_STAT=1`。
- SBL 读 AB metadata 选 slot：校验 CRC（错误则重新初始化默认 metadata）→ 跳过 `verity_corrupted=1` → 跳过 `tries_remaining=0`（unbootable）→ 优先 `priority` 高 → 其次 `successful_boot` 高 → 再次 `tries_remaining` 高；选中未 `successful_boot` 的 slot 则递减 `tries_remaining`。
- 槽状态：出厂态、成功态（启动到内核打印 `Slot $slot marked as successful.` 后置 `successful_boot=1`）、active 态（被 OTA 标记为下次优先，但尚未成功启动）、失败态（unbootable）。
- AB 状态转换场景：S1=出厂前（双出厂态），S2=出厂后 OTA 前（成功态 + 出厂态），S3.1/S3.2/S3.3=OTA 后（active/成功/成功 + 对面成功/失败/成功）。完整迁移表与逐格日志见 `reference/m57/M57 SBL启动特性介绍.md` §1.2。
- 客户问题 FAQ log（用于串口定位）。“触发场景”为日志出现原因摘要（自己/对面槽状态 × A/B × 异常断电/软复位），完整枚举见参考文档：

| FAQ log | 日志 | 触发场景（摘要） |
| --- | --- | --- |
| FAQ log0 | `Do not switch Safety abc. Rebooting...` | S1：出厂前双出厂态，自己 A/B，异常断电） |
| FAQ log1 | `€€€...`（ROM 44s 超时） | S1：出厂前双出厂态，自己 A/B，异常软复位 |
| FAQ log2（最常见） | `unbootable slot 0 tries: 0, corrupt: 0 unbootable slot 1 tries: 0, corrupt: 0 Wrong slot (ret = -22) Boot Slot: Unknown android_ab_manage failed:-24 boot_process failed: ret -24, flash_type 0x0, slot 0x0` | S1：出厂前双出厂态，自己 A/B，异常断电/软复位，且两槽可用次数都耗光（变砖） |
| FAQ log3 | `Firstly try to switch safety abc from %d to %d. Rebooting...` | 首次尝试切换 slot：OTA 前成功态自己是 B（异常断电/软复位）；OTA 后 active 自己 A（断电）或 B（断电/软复位）；OTA 后成功态自己是 B（对面失败/成功，断电/软复位） |
| FAQ log4 | `Loop slot%d to limit %d ... Remaining tries for Slot %d: %d Decrement the remaining tries (%d --> %d) for Slot %d. Rebooting...` | 同一 slot 复位达上限：OTA 前成功态自己 B（断电）或自己 A/B（软复位）；OTA 后成功态、对面失败，自己 B（断电）或自己 A/B（软复位） |
| FAQ log5 | `Remaining tries for Slot %d: %d Decrement the remaining tries (%d --> %d) for Slot %d. Rebooting...` | OTA 后双成功态：自己 B（断电）或自己 A/B（软复位） |
| FAQ log6 | `Forcefully switch safety abc from %d to %d. Rebooting...` | OTA 后自己 active、对面成功：自己 A/B（断电）或自己 B（软复位） |

## 复位 main 域（SBL）

- 用于 Rcore 侧复位 main 域后重新引导拉起 Acore：MCAL Reset 模块完成复位 main 后调用 `jump_reset_boot` 跳入 SBL main。
- `.data`/`.bss`：normal boot 直接使用并备份 `.data -> relocate addr`；reset main boot 从 relocate 地址恢复 `.data`、清 `.bss`（保留 remap cfg/board id）。
- AB 管理：normal boot 正常走 AB 流程；reset main boot 不走 AB 流程，直接使用 MCAL 跳转前的正常 slot（作为任务无法复位纠正）。
- RTOS img：normal boot 正常引导；reset main boot 对 ALL-on-OCM 镜像不引导，对 OCM+DDR 镜像只引导 DDR bin 部分（OCM 部分正在后台运行）。
- 成功跳转：normal boot 打印 `Jump Next` 跳 RTOS 入口；reset main boot 打印 `Jump Reset Back` 返回 MCAL Reset 跳入地址（返回 0）。失败时 normal 若开着 AB 触发 wdt4 复位，reset main 返回 `flash_boot` 返回值。
- 客户复位 main 失败常见原因：MCAL 客户 GPT 占用 timer4 与 SBL 冲突；OCM 开头 128K 未给 SBL 预留（AUTOSAR 不得复用）；Reset 场景 SBL 栈需至少预留 4KB；MCAL 运行 ADC 时 SBL reset main 不应再运行 ADC（主线已兼容）。

## BootCnt 方案（M57 架构）

- 提供 BOOT Count 信号：记录 SBL/SPL/RTOS/ATF/OP-TEE/U-Boot/Kernel 各阶段异常累计计数与成功启动计数。RomCode 阶段无法记录。
- 存储位置：metadata 与 metadata_bak 分区偏移 3K 起 1K（`struct boot_diag_info`，含 magic、crc32、`boot_fail_reason_t last_reason_info`、`sbl_boot_cnt_info_t`、`a55_boot_cnt_info_t`、`boot_okay_cnt`）。
- `fail_boot_stage`：BIT(0)=SBL … BIT(6)=KERNEL；`fail_boot_slot`：BIT(0)，0=slot A、1=slot B；`fail_handle_img_type`：BIT(0)=SPL(BY SBL) … BIT(6)=ROOTFS(BY U-Boot)。
- SBL 阶段直接写；A55 阶段先写 dummy 寄存器 `fcu_cfg sw_data5/sw_data6`，由 mcal `BootCnt_Demo` 轮询更新；成功启动由 Acore 启动脚本把 `sw_data5` 置 `0xffffffff` 标识。
- dump：`dd if=/dev/mtd20 of=metadata_3k_1k.bin bs=1k skip=3 count=1` 后 `hexdump -v -C`。
- 开启：`SafetyIsland/mcal/mcal_example/examples/Demo/config.mak` 打开 `SUPPORT_TEST_CASE_DEMO_BOOTCNT`，并在 `Mcal_demo.c` 关闭 `Fls_Demo`（nor nand）/ `Fls_LoopRd_Test`（only nand）。
- 该章节来自 M57 00 §13；AX637 SDK 文档未单列，使用时请确认平台支持。

## OTA 升级

- 车载可用性要求高，OTA 采用 A/B 系统方案，不支持 recovery。
- 支持：RSA 签名校验（默认与安全启动同密钥）、HASH、分区校验、软件版本校验、压缩、分区/文件/差分/AB 升级、失败回滚、镜像回读校验、自定义脚本、掉电安全、本地/网络升级。
- API：`abc` / `bcb` 操作 `/dev/link/misc` 与 `/dev/link/misc_bak`（`bcb` 传递 boot stage/status）。
- U-Boot 侧：`axera_ota` 命令，env 变量 `ota_server_ip` / `ota_xml` / `ota_spl` / `ota_uboot` / `ota_uboot_b` / `ota_atf` / `ota_dtb` / `ota_optee` / `ota_kernel` / `ota_rootfs` / `ota_param` / `ota_opt` / `ota_soc` / `ota_repartition`，`saveenv` 后执行 `axera_ota`。

## 故障定位

### BOOTROM 字符含义（串口输出）

`UA`=UART 下载、`US`=USB 下载、`SL`=SPI SLV 下载、`C0`=SPI CS0 启动、`C1`=SPI CS1 启动、`EU`=eMMC UDA 启动、`E`=eMMC BOOT 启动、`N2`=Nand 2K page、`N2M`=Multi Plane Nand 2K、`N4`=Nand 4K、`N4M`=Multi Plane Nand 4K、`NO`=Nor 启动、`SD`=SD 卡启动、`HP`=Hyper Flash 启动、`CAN`=CAN 下载、`EDU`=eMMC DUAL BOOT 启动。
失败类：`IF`=FLASH 初始化失败、`RF`=读镜像失败、`CF`=checksum 失败、`SIF`=CE 模块初始化失败、`PKF`=校验 PUBLIC HASH 失败、`SHF`=CE 算 HASH 失败、`RSF`=CE RSA 计算失败、`DF`=CE 解密失败、`AF`=读 AUTOSAR 镜像失败、`GF`=镜像解压缩失败、`ACF`=AUTOSAR checksum 失败、`AHF`=读 AUTOSAR Header 失败、`R2F`=读 Header 第二部分失败。`RS`=读镜像成功。

### 串口启动日志关键字

| 关键字 | 含义 / 定位方向 |
| --- | --- |
| `Slot $slot marked as successful.` | 当前 slot 启动到内核阶段，被标记为成功槽 |
| `Do not switch Safety abc. Rebooting...` | FAQ log0，出厂前双出厂态异常断电 |
| `€€€...`（乱码，ROM 44s 超时） | FAQ log1，出厂前双出厂态异常软复位 |
| `unbootable slot ... Wrong slot (ret = -22) ... android_ab_manage failed:-24` | FAQ log2，出厂前两槽可用次数耗光、AB 均不可用，最常见变砖场景 |
| `Firstly try to switch safety abc from %d to %d. Rebooting...` | FAQ log3，首次尝试切换 slot |
| `Loop slot%d to limit %d ... Remaining tries ... Rebooting...` | FAQ log4，同一 slot 复位达上限，停止等待排查 |
| `Remaining tries for Slot %d: %d ... Rebooting...` | FAQ log5，OTA 后双成功态下递减重试次数 |
| `Forcefully switch safety abc from %d to %d.` | FAQ log6，OTA 后 active 槽强制切换 slot |
| `Jump Next` / `Jump Reset Back` | SBL 正常引导 / 复位 main 引导返回 |

> 定位口诀：先按日志确定“自己/对面槽状态 + 自己 A/B + 异常断电（掉电，复位计数不持久，可无限次）或异常软复位（复位计数受上限约束，如 255 次）”，再对照 `reference/m57/M57 SBL启动特性介绍.md` §1.2 的场景表判断是 AB 交叉启动、可恢复切换还是已变砖。
