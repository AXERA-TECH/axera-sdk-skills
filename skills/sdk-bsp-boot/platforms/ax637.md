# Platform: ax637

AX637 / AX637R 是 M57 架构下的车载/工业视觉子平台。本文件只描述 board/SDK 层与 M57 的差异；启动链路、构建框架、内存与分区机制、BOOTROM 方案、OTA 等公共内容见 `platforms/m57.md`（通过 `extends: m57` 自动叠加，同名条目以本文件为准）。

注意：BootCnt 为 M57 特性，AX637 / AX637R 不支持。

事实来源：`reference/ax637/00 - AX SDK 使用说明.md`、`reference/ax637/637-boot类问题.md`。

## AX637 目标平台配置

- PLAT 命名规则同为 `BOARDNAME_FLASHTYPE`。
  - `BOARDNAME`：`ax637_demo`（安防）/ `ax637r_demo`（边缘）。
  - `FLASHTYPE`：`only_nand`（Safety 与 Main 镜像都放 Main Nand）/ `only_emmc`（都放 Main eMMC）。
  - 完整 PLAT：`ax637_demo_only_nand` / `ax637_demo_only_emmc` / `ax637r_demo_only_nand` / `ax637r_demo_only_emmc`。
- 平台配置目录：`build/platforms/axera/<PLAT>/config.mk`，如 `build/platforms/axera/ax637_demo_only_emmc/config.mk`。修改前先与用户确认目标 PLAT。
- 全量编译：`make PLAT=ax637_demo_only_nand clean all install axp`。
- U-Boot defconfig 示例：`ax637-demo-only-nand_defconfig`；Kernel defconfig 示例：`ax637-tiny_defconfig`。
- 关闭 ATF/OP-TEE：`config.mk` 中 `SUPPORT_ATF := FALSE`、`SUPPORT_OPTEE := FALSE`；编译生成 axp 时会自动删除对应分区。

## AX637 启动链路

启动链路与 M57 架构一致（BootROM → SBL → SPL → BL31 → OP-TEE → U-Boot → Kernel），DDR 初始化同样在 SBL 阶段完成，见 `platforms/m57.md` §启动链路，本文件不再重复。

## U-Boot 简化引导命令（AX637）

默认走 `distro_bootcmd`，见 `platforms/m57.md` §U-Boot 引导内核方式。若客户场景无需通用 distro 流程，可按“是否 AB 启动 × 是否安全启动”选择对应 BOOTCMD（以 only_nand 为例；only_emmc 场景把 `load mtd` 换成 `load mmc`）：

| 是否 AB | 是否安全启动 | BOOTCMD |
| --- | --- | --- |
| 否 | 否 | `load mtd 0:9 0x110000000 Image.axgzip` + `load mtd 0:9 0x118000000 <dtb>` + `booti 0x110000000 - 0x118000000` |
| 否 | 是 | `load mtd 0:b 0x10e000000 Image.sign` + `bootm 0x10e000000`（启用 cipher 时为 `Image_enc.sign`） |
| 是 | 否 | `setexpr tmp_bootpart 0xf + ${bootslot};` + `load mtd 0:${tmp_bootpart} 0x110000000 Image.axgzip` + `load mtd 0:${tmp_bootpart} 0x118000000 <dtb>` + `booti 0x110000000 - 0x118000000` |
| 是 | 是 | `setexpr tmp_bootpart 0x13 + ${bootslot};` + `load mtd 0:${tmp_bootpart} 0x10e000000 Image.sign` + `bootm 0x10e000000`（启用 cipher 时为 `Image_enc.sign`） |

kernel 分区号可通过 `part list mtd 0` / `part list mmc 0` 或直接查看分区配置文件确定。

## 内存调整（AX637）

- 与 M57 一致：修改对应平台 `build/platforms/axera/<PLAT>/config.mk` 中的 `SYSTEM_MEMORY_SZ` 与 `LINUX_MEMORY_SZ`（两者之差即 CMM 大小），详见 `platforms/m57.md` §内存规划；Inline ECC 配置同样复用 M57 说明。
- AX637 默认 DDR 1 GiB，Linux 最大 384 MiB（0x18000000），CMM 640 MiB。

## AX637 分区（only_nand / only_emmc）

- 分区表位置：`only_nand` 下分区表信息在 `metadata` / `metadata_bak` 分区，U-Boot axdl 烧录阶段写入（该分区为 Axera 存放分区表用，客户不要用于扩展）；`only_emmc` 下分区表信息在 offset=0 起 1M GPT 空间，因此 SBL 分区从 1M 地址起。
- AB 与非 AB 使用不同文件：`build/platforms/axera/<PLAT>/partitions.json`（AB）/ `partitions_without_ab.json`（非 AB）；调整大小改对应文件的 `size`。
- `size` 单位 KB，且必须是 block size 的整数倍：NAND 为 256K（W25N04LW）。

AX637 默认分区（以 `ax637r_demo_only_nand` AB 表为例，KB）：

| 分区 | size | 说明 |
| --- | --- | --- |
| sbl_a / sbl_b | 768 | |
| metadata / metadata_bak | 768 | no-image |
| spl_a / spl_b | 1024 | |
| rtos_a / rtos_b | 4096 | |
| misc / misc_bak | 768 | no-image（仅 AB 需要） |
| ubootenv / ubootenv_bak | 256 | no-image |
| uboot_a / uboot_b | 1536 | |
| atf_a / atf_b | 768 | |
| optee_a / optee_b | 1280 | |
| kernel_a / kernel_b | 10240 | |
| rootfs_a / rootfs_b | 153600 | |
| userdata | 102400 | |

分区大小调整约束：

1. NAND 场景颗粒存在出厂坏块/使用坏块，SDK 默认分区已为各分区预留足够 block 用于跳坏块（满足生命周期 10ppm 不良率）；即使极致裁剪也必须预留 block。
2. NAND 场景没有独立 hsm 分区，hsm 镜像附在 SBL 镜像之后作为 256K 输出（前 128K 为 SBL、后 128K 为 hsm），因此 SBL 分区中实际 SBL 镜像要按 256K 考虑。
3. AB 场景下 SBL 分区大小无论 eMMC 还是 NAND 都必须用 SDK 默认值（NAND 768K、eMMC 128K），因为 RomCode 找 B 分区的偏移就是按该大小计算。

非 AB 且不考虑使用坏块时的启动分区优化：

- sbl（仅非 AB 支持）：block256 → 512K；block128 → 384K（注意不能改 256K，需考虑 hsm 附加）。
- metadata / metadata_bak：block256 → 256K；block128 → 128K；不建议删掉 metadata_bak。
- misc / misc_bak（仅 AB 需要）：优化策略同 metadata / metadata_bak。
- 修改 sbl/metadata 大小除改分区文件外，还需在 U-Boot `menuconfig` 搜索 `LUA_SBL_SIZE_IN_NANDFLASH` / `LUA_METADATA_SIZE_IN_NANDFLASH` 同步修改。
- 工业视觉 `ax637_demo_only_nand` 平台分区表已把 kernel 之前的启动分区调整为只多留 1 个 block 用于坏块场景；客户做小容量颗粒裁剪时只需按实际产品调整 kernel/rootfs/userdata 大小。若想多留 block 延长寿命，调大对应启动分区即可。

新建/删除分区：

- 分区表中 `sbl*` ~ `rtos*` 为 MCU 侧使用及引导镜像，默认不支持在中间增删。
- `misc*` / `ubootenv*` 起及其后为 Acore 侧使用及引导的镜像，支持增删自定义分区。新增分区除改 `partitions.json` 外，还需在 U-Boot 白名单数组 `main_part_id[]`（`boot/uboot/u-boot-2022.10/board/axera/common/m57/common.c`）加入分区名，否则会被过滤。
- 若要让自定义分区镜像进入 axp 打包，还需修改打包脚本 `scripts/axp_make.sh`（将新增镜像路径填入）；不用 SDK axp 打包逻辑则无需该步骤。

## 调试串口波特率

- AX637 / AX637R 调试串口默认 115200（与安防常用波特率一致）。修改需同时覆盖 SBL、RT-Thread、SPL、U-Boot、Linux 等多个模块，修改点较多。
- trunk 已按场景区分：安防/边缘 115200，车载 921600；ep 分支若修改需与客户对接确认。

## AX637 boot 类问题

详见 `reference/ax637/637-boot类问题.md`，要点：

1. 内核启动复杂化：平台建议维持 `distro_bootcmd`，不建议改为“直接从 ext4 读 Image.axgzip/dtb 再 booti”的传统方式（兼容性较弱）；已更新 00-SDK §8.4 章节说明默认引导方式、环境变量与各组合简化命令。
2. 环境变量过长：distro boot 引入较多脚本环境变量，产线烧录易被破坏导致无法启动；处理方案同 No.1。
3. 分区获取方式改到 bootargs：安防客户希望分区表放在 bootargs（兼容 650/620q），平台已兼容处理。
4. Linux 启动 depmod/insmod 报错：`S00modprobe_pos` 为 insmod 实现、`S33modprobe_post` 为 modprobe 实现（无依赖 ko 并行加载加速）；只读文件系统风险 ep1.11/trunk 已修复（`/usr/sbin/depmod -b /tmp -o /tmp`）。
5. reserve_memory、hwinfo dts：Linux reserved_memory 默认在各 dts；U-Boot 会动态新增 3 个 node（`atf_reserved`、`optee_reserved`、`bootlog_reserved`，取决于 build plat config 与 U-Boot defconfig 地址）；`hw_info_display` 由 U-Boot 填写（version/board-id/chip-name/bootlog-record/boot-device/abort/boot-slot/cmm-size/cmm-start），因多为动态启动信息，比 dts 写死兼容性高。
6. 调试串口波特率：见上节。
7. U-Boot 不支持 usb fastboot（`AX637_R1.26.1601` / `AX637_SDK_V1.11.0_P2`）：驱动方案已支持，后续版本评估合入主线。
