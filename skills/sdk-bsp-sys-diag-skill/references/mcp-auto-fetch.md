# 有 Jira 链接且 MCP 可用时：自动拉取工单与日志（Phase 0 增强）

当用户直接给出 Jira 工单链接（如 `https://jira.example.com/browse/AX###-####`）**且当前会话存在 Jira MCP 工具**时，可以半自动地把工单详情、附件日志拉下来作为 Phase 1/2 的输入，省去用户手工粘贴。

> **可移植声明**：不同会话里 MCP 工具名可能不同、也可能根本没有。使用前先确认工具是否存在；不存在就退回纯问答（让用户粘贴现象与日志）。下面以通用工单工具能力描述，实际工具名以当前会话注册的为准。

## 流程

1. **读工单详情**（只读）：用工单详情查询工具（传入工单号）读描述、评论、附件清单。
   - 从**描述**取现象、出问题阶段；从**评论**常能直接拿到调用序列与客户自查结论（如标杆案例中评论里就写明了 `GetChnFrame→Mmap→Munmap→ReleaseChnFrame→MemFree` 这串序列）。
   - 记下附件里的日志文件（`*.log` / `*syslog*` / `dmesg*`）。

2. **下载附件日志**（会落盘/外发，属谨慎操作）：用工单附件下载工具（传入工单号与本机输出目录）；若工具返回需在本机执行的下载命令，在本机执行该命令把附件保存到 `output_dir`。
   - 只下载与诊断相关的日志/符号文件，别无差别全量下载。

3. **扫描日志**：对落盘的日志跑 `scripts/scan_cmm_log.sh <logfile>`，按 `log-keywords.md` 判读，抽出 `phyaddr`。

4. **回到主流程**：把工单里的现象、调用序列、日志扫描结果，喂给 Phase 1（分诊）→ Phase 2（判读）→ Phase 3/4/5。工单评论里客户已验证的信息（如"删掉某次释放后不再复现"）可直接用于 Phase 5 的证据闭环。

## 注意

- **只读优先**：默认只 `get_*` / `download`。除非用户明确要求，不要往工单里写评论、改状态。
- **符号文件**：若附件含 `vmlinux` 之类，可用于需要地址→符号定位的深挖，但通常先靠日志关键字与 proc 反查就能定位，不必一上来就展开。
- **拿不到 MCP / 附件直链 403**：退回纯问答，请用户在已登录的浏览器里下载后把日志贴进来，或按 `log-capture-guide.md` 重新抓一份。
