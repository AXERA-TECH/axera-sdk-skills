# Platform: m57

M57 Linux/QNX 主域与 SafetyIsland MCU 域的 IPC、RPMsg、RPZC 公共事实。具体操作前先确认主域 OS、对端核、板型、SDK 版本和目标配置文件；本页示例不能替代目标工程中的实际 DTS/MCAL 配置。

## 架构与数据通道

| 能力 | 控制/通知 | payload | 适用场景 |
|---|---|---|---|
| RPMsg / IPC | mailbox 或 GPIO 类通知，virtqueue/rpmsg_lite 管理 | shared-memory virtqueue ring buffer | 控制消息和小数据 |
| RPZC / IPCZC | `axera,rpzerocopy` RPMsg service 传递 create/destroy/transfer/ACK | shared DMA buffer、IRAM 或约定 DDR | 大块数据、减少拷贝 |

mailbox/GPIO 只负责通知，不是业务 payload 通道。RPZC 依赖 RPMsg 链路，必须先建立底层 endpoint/service。

## Linux 配置

### Kernel config

RPMsg 基础能力需要：

```text
CONFIG_MAILBOX=y
CONFIG_AXERA_MBOX=y
CONFIG_RPMSG_CHAR=y
CONFIG_RPMSG_CTRL=y
CONFIG_RPMSG_AXERA=y
```

RPZC 还需要：

```text
CONFIG_RPZC_SERVICE_RPMSG=y
CONFIG_RPZC_CONTROLLER=y
```

启用后应看到 `/sys/class/rpmsg/`、`/dev/rpmsg_ctrlX`；RPZC controller 正常 probe 后应看到 `/sys/class/rpzc/` 和 `/dev/rpzc_ctrlN`。

### DTS 资源

M57 基础 `m57.dtsi` 定义 mailbox、`rpmsg0`/`rpmsg1` 与 `rpzc_ctrl0`；平台 `.dts` 才负责分配 reserved-memory 并启用目标节点。reference 中 `demo_nor_nand` 示例包含：

- `rpmsg0`：A55 与 R5F0，mailbox slot `0/1`，destination core `3`。
- `rpmsg1`：A55 与 R5F1，mailbox slot `2/3`，destination core `4`。
- `rpmsg0` 控制区示例为 `0x400000`，ring data reserved-memory 示例为 `0x401000`；`rpmsg1` 示例为 `0x402000`/`0x403000`。
- `rpzc_ctrl0` 通过 `rpmsgch = <&rpmsg0>` 依附 `rpmsg0`，`rpzcctrl-index = <0>`；RPZC reserved-memory 示例起始于 `0x406000`、长度 `0x8000`。
- `ipc-gpio = <&gpio5 31 0>` 用于 MCU AUTOSAR 多核占用 mailbox 中断的方案。若恢复 mailbox 中断，Linux DTS 与 MCU MCAL 必须同步修改。

这些地址仅是参考板示例。其他板型必须从目标 DTS 和 MCU `ReservedMemory_cfg.h` 获取实际值，不得直接照搬。

## Linux 用户态

### RPMsg endpoint

1. 等待远端启动、transport probe 和 name service，检查 `/sys/class/rpmsg/`。
2. 打开 `/dev/rpmsg_ctrlX`，用 `RPMSG_CREATE_EPT_IOCTL` 和 `struct rpmsg_endpoint_info` 创建 endpoint。
3. 打开生成的 `/dev/rpmsgX`，通过 `read()`/`write()` 收发。
4. 在 endpoint fd 上调用 `RPMSG_DESTROY_EPT_IOCTL` 后关闭。

`name` 长度为 32 字节；不用固定地址时使用 `RPMSG_ADDR_ANY`。显式配置地址时，本端 `src/dst` 必须与对端 `dst/src` 交叉匹配；参考指南还要求普通业务地址小于 `0x400`，其余范围留给 name service。ioctl 编号必须来自 `include/uapi/linux/rpmsg.h`。

### RPZC buffer 生命周期

1. 打开 `/dev/rpzc_ctrlN`。
2. 用 `RPZC_CTRL_DEV_IOCTL_CREATE_BUF` 和 `struct rpzc_buffer_info` 创建跨端同名、长度一致的 buffer，获得 `/dev/rpzc-<name>`。
3. 打开 buffer 设备并 `mmap()` payload；单个 buffer 设备同一时间只允许一个 opener。
4. 调用 `RPZC_BUF_DEV_IOCTL_CHECK_AVAIL`，确认远端已完成同名 buffer 协商。
5. 发送端通过 `RPZC_BUF_DEV_IOCTL_TRANSMIT_BUF` 提交合法的 `offset` 和 `data_len`；同步模式等待远端 ACK。
6. 接收端通过 `RPZC_BUF_DEV_IOCTL_RECEIVE_BUF` 获取描述符；先消费 payload，`need_ack != 0` 时再调用 `RPZC_BUF_DEV_IOCTL_REPLY_ACK`。
7. 关闭 buffer fd，通过 `RPZC_CTRL_DEV_IOCTL_DESTROY_BUF` 销毁。关闭 control fd 时，内核会清理该 fd 未销毁的 buffer。

控制消息最大 96 字节，buffer name 长度为 32 字节。`RECEIVE_BUF` timeout：负值表示可中断无限等待，`0` 表示不等待，正值表示毫秒；业务需处理 `-ETIMEDOUT` 和信号中断。

## QNX 配置与使用

### 驱动与配置结构

QNX IPC 基于 RPMSG-LITE，默认提供 `rpmsg0` 和 `ipczc0`。驱动与用户态接口均位于 `kernel/osdrv/open_drv/ax_ipc/`：

- `driver/cfg/`：`Ipc_cfg.h/c`、`Ipc_zc_cfg.h/c`、`ReservedMemory_cfg.h`；
- `driver/rpmsg/`：IPC transport、endpoint、ring buffer 和通知实现；
- `driver/rpzc/`：IPCZC buffer、描述符和 ACK 实现；
- `driver/ax_rpmsg_drv.c`：QNX resource manager/driver 入口；
- `lib/`：`libax_rpmsg` 用户态接口，公共声明在 `lib/public/ax_rpmsg.h`。

修改配置前先确认目标 QNX image 实际编译并启动了 `ax_rpmsg_drv`，不要仅凭目录存在判断驱动已运行。

### EPT 配置

`Ipc_cfg.h/c` 中每个 EPT 至少核对 `UniqueId`、`LinkId`、`LocalAddr`、`RemoteAddr`、`NeedInform`、`EptName`、`RxEnable`、`RbBuffer` 和 `RbSize`：

- 固定地址模式使用具体的 `LocalAddr`/`RemoteAddr`，本端 local 必须与远端 remote 交叉匹配，且不能相同；
- name service 模式可使用 `RL_ADDR_ANY`，并配合 `NEED_NS` 和具体 `EptName`；固定地址且不发布服务时使用 `NEED_NOT_NS`；
- endpoint 地址必须小于 1024，地址冲突会被拒绝；单个物理通道的 `MaxEptNumber` 不应大于 20；
- EPT 配置变化必须同步 MCU/RTOS 对端，不能只改 QNX 一侧。

### IPCZC、内存与通知

`Ipc_zc_cfg.h/c` 中核对 `EndpointIdx`、`BufferID`、`BufferName` 和 `BufferSize`；IPCZC 使用前必须先使能对应 IPC endpoint，远端 buffer 的 name、长度和业务方向必须一致。

当前工程默认 `IPC_ZC_BUFFER_BY_DDR=0`，即使用 IRAM。切换 DDR 时必须同时修改 QNX reserved-memory、`ReservedMemory_cfg.h` 中的 DDR 地址（如 `AX_RESV_MEM_DDR_ADDR_IPCZC0`）、`Ipc_zc_cfg.h` 和 MCU 端 IPCZC 模式/地址；用 `pidin syspage=asinfo` 检查 reserved-memory 已注册且不与其他区域重叠。不要把某个 demo 的地址直接套到其他 board。

当前工程默认 `IPC_GPIO_TRIGGER_IRQ_EN=1`，采用主域 GPIO + SPI slave CS、MCU 回主域 mailbox 的通知方案，以避免占用 AUTOSAR 多核所需的 mailbox 中断资源。改用 mailbox 时将其设为 `0`，并同步修改 MCU MCAL/RTOS 的通知配置；两端不能混用方案。

### 测试与诊断

- IPC 基础收发：`sample_ipc_rpmsg`；
- IPCZC：`sample_ipc_rpmsg -z 1 [-t n]`；
- 资源核对：`pidin syspage=asinfo`，并结合 QNX resource manager 日志确认 driver、EPT 和 buffer 已创建。

单次 EPT 业务 payload 最大 112 字节；较大数据应使用 IPCZC。远端 reset/remove 后，旧 endpoint、fd 或映射不保证有效，必须重新枚举、初始化并重新协商 buffer。

## SafetyIsland MCU / MCAL

### IPC

主要 API：`IpcInitial()`、`IpcEndpointCbRegister()`、`IpcEndpointCbUnRegister()`、`IpcSendData()`、`IpcEptLinkStatusCheck()`、`IpcOpenRxProcess()`、`IpcCloseRxProcess()`、`IpcReadData()`、`IpcMainDomainStatusCheck()` 和 `IpcMainFunctionHandleAllLinkup()`。

- MCU 配置决定 physical channel、endpoint、local/remote address、name service、ring buffer 和 mailbox/中断方式。
- 一个物理通道使用 4 KB shared memory、32 个 ring buffer；每个 ring 128 字节，扣除 16 字节 RPMsg header 后业务最大 112 字节。
- 发送前使用 `IpcEptLinkStatusCheck()`；异步模式先注册 callback，同步/轮询模式按集成文档打开接收处理。
- endpoint 数量上限按当前 MCAL 配置评估；Linux 补充资料给出的 MCAL 上限为 20，不能只增加枚举而忽略静态 ring buffer 和启动开销。

### IPCZC

主要 API：`IpcZcCallbackFuncRegister()`、`IpcZcBufferIsAvailablebyId()`、`IpcZcBufferCreate()`、`IpcZcBufferDestroy()`、`IpcZcBufferHasData()`、`IpcZcWholeInitial()`、`IpcZcWholeUninitial()`、`IpcZcGetBufferInfor()`、`IpcZcTransferData()`、`IpcZcLinkStatusCheck()`、`IpcZcAckStatusCheck()` 和 `IpcZcMainFunctionHandleAckErr()`。

- master 端申请 buffer 并将地址/长度同步到 remote；跨端通过 `BufferName` 匹配。
- 控制 endpoint 使用 name-service 名 `axera,rpzerocopy`，普通业务 endpoint 不得复用。
- 枚举中的 Read/Write 方向在两端可能镜像，必须结合 `BufferName` 和业务数据流确认。
- 同步发送端在 ACK 完成前不得复用 buffer；MCU 当前 `IPC_ZC_POLLING_ACK_EN` 配置为 `0`，改变时需补充 CPU 占用、timeout 和并发测试。
- reset/reinit 使用 `IpcRpmsgReset()`、`IpcRpmsgReinit()`；恢复后重新注册 callback 并检查 link status。

## SafetyIsland RTOS

RTOS 的 IPC/IPCZC 框架与 MCAL 使用相同的跨端通信契约，但不能直接假设配置完全相同。实现和静态配置位于 `SafetyIsland/rt-thread/bsp/m57/drivers/ipc/`，包括 `cfg/`、`rpmsg/` 和 `rpzc/`；实际工程仍需核对 endpoint、mailbox slot、shared memory、buffer name/size/方向和通知方式。

- RTOS/bare-metal 端使用不同配置时，Linux 或其他主域的 DTS 地址、物理通道和 endpoint 不能直接照搬。
- AX637/AX637R 的 RT-Thread 镜像可通过 `sample_ipc_test` 和 `sample_ipczc_test` 进行 IPC/IPCZC 测试；只有对应应用被编入当前镜像时，命令才可用。
- 测试前确认 RTOS 端初始化、name service、link status、buffer 协商和 ACK 状态；reset 后重新初始化并重新检查 callback/link。
- RTOS 的 ring buffer 锁、callback 上下文和周期任务由具体集成环境决定，不能套用 MCAL 或 Linux 的并发假设。

## 跨端一致性检查

| 项目 | 主域 | MCU/RTOS 域 | 检查要求 |
|---|---|---|---|
| endpoint 地址 | Linux UAPI 或 QNX `Ipc_cfg.c` | MCAL/RTOS `Ipc_cfg.c` | local/remote 交叉匹配 |
| service/name | endpoint/name service | endpoint 配置 | 完全一致；RPZC 控制 service 固定为 `axera,rpzerocopy` |
| RPZC buffer | name、size、方向 | `BufferName`、size、方向 | 名称/长度/业务方向一致 |
| shared memory | DTS reserved-memory 或 QNX IRAM/DDR | MCAL `ReservedMemory_cfg.h` 或 RTOS 配置 | 地址、长度、不重叠 |
| 通知 | mailbox slot、destination core、`ipc-gpio` | MCAL/RTOS mailbox/GPIO/SPI 配置 | 方案与 slot 完全一致 |
| reset | device/service remove 与重新 probe | reset/reinit | 双方重新建立 endpoint/buffer |

## 故障定位

1. **编译配置**：Linux 核对 RPMsg/mailbox/RPZC config；QNX 核对 `ax_ipc` 是否构建并启动；MCAL/RTOS 核对生成配置和驱动是否编入镜像。
2. **资源配置**：Linux 核对目标 DTS 与 MCAL/RTOS 的地址、长度、slot、destination core 和中断方式；QNX 核对 `Ipc_cfg.h/c`、`Ipc_zc_cfg.h/c`、`ReservedMemory_cfg.h`、`IPC_ZC_BUFFER_BY_DDR`、`IPC_GPIO_TRIGGER_IRQ_EN` 及 `pidin syspage=asinfo`，确认资源不重叠且与对端一致。
3. **probe 与枚举**：Linux 检查 `dmesg`、`/sys/class/rpmsg/`、`/sys/class/rpzc/` 和设备节点；QNX 检查资源管理器状态。
4. **endpoint**：记录 name、src、dst、name service 和 link status。link 未建立时 send 失败是预期现象。
5. **RPZC**：记录 buffer name、len、available、offset、data_len、need_ack、timeout、ioctl 返回值和 errno。
6. **SafetyIsland 状态**：核对 MCAL/RTOS 的 `IpcInitial()` / `IpcZcWholeInitial()` 或等效初始化是否完成，并检查 `IpcEptLinkStatusCheck()` 或 `IpcZcLinkStatusCheck()` 的结果。RTOS 端同时确认 `sample_ipc_test` / `sample_ipczc_test` 是否已编入镜像。
7. **接收并发**：出现 `previous recv data not treated` 时，先处理上一笔 payload 并完成 ACK，再允许新数据。
8. **reset**：确认远端是否重启、MCAL/RTOS reset/reinit 是否执行、主域 service 是否重新 probe、callback 是否重新注册。
9. **锁**：BareMetal、RTOS、AUTOSAR 的锁实现不同；默认 MCU RPMsg 锁可能为空，只在 endpoint 操作 ring buffer 的临界区增加合适保护。

## 测试矩阵

- RPMsg 双向收发、name/src/dst 不匹配、远端未启动、空接收、endpoint destroy。
- RPZC create/check available/mmap/transmit/receive/ACK/destroy。
- 重复 buffer name、单 buffer 多 open、未 ready 发送、offset/data_len 越界、ACK timeout。
- 远端 reset/remove 后旧 fd/mapping 失效，以及重新枚举和恢复。
- UT 由主域平台统一触发；生成代码分别集成到主域 `ut/` 与 MCU `SafetyIsland/mcal/mcal_example/examples/Demo/`。
- RTOS 平台应确认当前镜像已编译 IPC 测试应用；AX637/AX637R 可使用 `sample_ipc_test` 和 `sample_ipczc_test` 覆盖基础收发、buffer 协商和 ACK。
