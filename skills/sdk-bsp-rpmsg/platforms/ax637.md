# Platform: ax637

AX637 / AX637R 的 IPC、RPMsg、RPZC 路由层。AX637/AX637R 不支持 QNX，QNX 相关修改无需同步到 AX637。当前 `reference/` 没有独立的 AX637 通信指南，因此本文件不声明未经资料确认的 AX637 专属 endpoint、shared-memory 地址、mailbox slot 或设备节点；仅复用 [`m57.md`](m57.md) 中适用的 Linux、MCU/RTOS 通信规则。

## 适用规则

- 路由命中 AX637/AX637R 后，加载 `platforms/m57.md` 中适用的 Linux、MCU/RTOS 公共流程，再应用本页的确认要求；跳过其中仅适用于 M57 的 QNX 内容。
- AX637/AX637R 不支持 QNX，不读取 QNX `ax_ipc` 配置，也不将 QNX 文档或配置修改同步到 AX637。
- 不得把 M57 `demo_nor_nand` 的物理地址、GPIO、DTS 节点编号直接写入 AX637 配置。
- 修改前必须从目标 AX637 SDK 的实际 DTS、kernel config 和 SafetyIsland 配置中读取 board 事实。
- 若目标 SDK 使用 RT-Thread 而非 MCAL，不能套用 MCAL API；应先定位该 SDK 的 RPMsg/RPZC 实现和配置，再补充平台文档。当前 RT-Thread IPC/IPCZC 驱动路径为 `SafetyIsland/rt-thread/bsp/m57/drivers/ipc/`，包含 `cfg/`、`rpmsg/` 和 `rpzc/`。

## Board 级确认清单

| 主题 | 必须确认的事实 |
|---|---|
| 主域 | 非 QNX 主域；如使用 Linux，确认内核版本与实际驱动目录 |
| MCU 对端 | R0/R1、RT-Thread/MCAL/其他 RTOS，及其初始化 API |
| 物理通道 | 实际 `rpmsgN`、destination core、mailbox slot 与通知方式 |
| endpoint | local/remote address、name、name service 和数量上限 |
| RPZC | controller 依赖的 RPMsg 通道、buffer name/size/方向与 ACK 模式 |
| shared memory | DTS/RTOS 中的地址、长度、cache 属性及是否与其他区域重叠 |
| reset | 主域 transport/service remove/reprobe 与远端 reset/reinit 的恢复流程 |

## 事实来源

1. 先读 [`../reference/_index.md`](../reference/_index.md)，确认 AX637 不支持 QNX；QNX 资料仅适用于 M57，不同步到 AX637。
2. 将 [`m57.md`](m57.md) 中适用的 Linux、MCU/RTOS 协议、UAPI、buffer 生命周期和诊断顺序作为公共参考，跳过其 QNX 专属内容。
3. 所有 AX637 专属数值和源码路径必须由目标 SDK 现场验证；发现稳定差异后，再补充本页及 `reference/_index.md`，并注明来源。

## RT-Thread 测试入口

AX637/AX637R 的 RT-Thread 镜像可提供 `sample_ipc_test` 和 `sample_ipczc_test`，分别用于 IPC 与 IPCZC 基础测试。命令是否可用取决于应用是否编入当前镜像；测试前仍需确认 endpoint、mailbox slot、shared memory、buffer name/size/方向和对端配置一致。

## 禁止推断

- 不因路径中出现 `m57` 就断言目标是 M57 board；AX637 SDK 可能复用 M57 架构目录。
- 不因存在 `configs_ax637*` 就推断其 endpoint、memory 或 mailbox 配置与 MCAL 文档相同。
- 不在缺少来源时给出 AX637 专属 DTS 地址、`PLAT` 名、设备节点编号或测试命令。
