# Platform: ax637

AX637 / AX637R SDK board 层 Secure Boot 事实与路径。AX637 基于 M57 架构，本文件仅
覆盖 board/SDK 层差异；公共的信任链、配置、产物、Download/AXDL 和 eFuse 规则位于
`<SKILL_ROOT>/platforms/m57.md`（`extends: m57` 要求先显式读取父平台，再读取本文件）。

## AX637 目标平台配置

**关键 config.mk 位置**（必须先由用户确认具体 `PLAT`；示例：AX637 eMMC）：

```
build/platforms/axera/ax637_demo_only_emmc/config.mk
```

同一芯片下多个 board（不同启动介质、A/B 策略）各自有独立的 `config.mk`；操作时先确认
路径与用户目标一致，避免改到其他 board 的同名文件。

## ax637_demo_only_emmc：先检查 HSM 分区

对 `ax637_demo_only_emmc` 使能 Secure Boot 时，先确认实际生效的分区表中包含 HSM 固件分区。
部分默认表缺少此项，仅设置 `SECURE_BOOT := TRUE` 会导致 BootROM 无法加载 HSM 固件，进而无法完成安全启动校验。

1. 从目标 `config.mk` 确认 `SUPPORT_AB` 和本次构建最终选中的 `PARTITIONS_JSON`；
   `asan`/`kdebug`、`ubuntufs` 等参数可能覆盖表名。修改实际选中的表。
2. 非 A/B 表应包含 `hsm`；A/B 表应包含 `hsm_a`、`hsm_b`。缺失时补齐，已有时保留。
   当前 SDK 的 `partitions.json` 已有 `hsm_a/hsm_b`，但默认 `SUPPORT_AB := FALSE` 选择的
   `partitions_without_ab.json` 缺少 `hsm`，因此只检查 `partitions.json` 会漏掉问题。
   当前表使用 `unit: "1K"`，已有 HSM 分区大小为 `"128"`；非 A/B 表可在 `sbl` 后添加：

   ```json
   { "name": "hsm", "size": "128" }
   ```

   位置、大小与对齐须符合本版本 BootROM 布局；修改后重新核对后续分区偏移及容量。
3. 确认 HSM 固件进入打包映射：`build/scripts/axp_make.sh` 将
   `build/scripts/imgsign/eip130_fw.bin` 复制为 `eip_m57.img`，
   `HSM_PATH` / `HSM_A_PATH` / `HSM_B_PATH` 分别对应上述分区。
   完成条件是最终 AXP 分区清单包含所需 HSM 分区及其固件，烧写时更新对应分区布局和镜像。
   仅生成固件文件或修改 JSON 尚未完成使能。

此独立分区补齐要求针对 `ax637_demo_only_emmc`。`ax637_demo_only_nand` 的
`build/scripts/imgsign/sbl_sign.py` 会将 HSM 固件合入 SBL 镜像，由同一分区承载，
沿用该打包方式；其他平台按各自已有布局核对，不套用 eMMC 的新增分区步骤。
