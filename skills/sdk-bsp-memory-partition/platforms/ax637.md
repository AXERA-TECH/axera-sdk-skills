# Platform: ax637

AX637 / AX637R DDR memory、FLASH partition 和镜像打包所需的平台事实、路径与约束。

## DDR 与 Linux/CMM 基线

- 文档化的 1 GiB DDR 示例最多分配 Linux 384 MiB、CMM 640 MiB（large physically contiguous memory）。ATF/OPTEE 和 image-loading reservation 还会进一步细分 Linux 可见内存。
- Linux 和 CMM 的物理范围必须不重叠；实际板卡内存、固件 reservation 和模块状态必须以目标硬件为准。
- 文档化默认 Linux memory size 为 `0x18000000`（384 MiB）。
- **Linux 内存大小的真正入口是 `build/platforms/axera/<platform>/config.mk` 的 `LINUX_MEMORY_SZ`**（编译进 U-Boot）。AX637 的 DTS 中**没有静态 `memory` 节点**——Linux 可见内存由 U-Boot 启动时通过 `ft_system_fixup_memory()` 动态 fixup 生成（DTS 的 `reserved-memory` 也标注 `/* filled by u-boot */`）。也可用 U-Boot 环境变量 `linux_mem` 运行时覆盖。
- 修改后需重新编译 U-Boot 并打包镜像；`SYSTEM_MEMORY_SZ` 保持不变时，CMM 大小按 `SYSTEM_MEMORY_SZ − LINUX_MEMORY_SZ` 自动调整。

## CMM 配置

- `load_modules.sh` 位于所选 platform build tree 的 initialization 目录；修改后重建并打包 `rootfs.img`，再通过 AXDL 刷入。
- 文档化示例：

```sh
insmod /opt/ko/ax_cmm.ko cmmpool=anonymous,0,0x118000000,640M
```

- 可写目标上可检查 `/usr/bin/load_modules.sh`；只读 filesystem 必须重建 image。CMM start/size 要与 DDR map 和 Linux reservation 一致。

## Partition source of truth

- 分区顺序以 `build/platforms/axera/<platform>/partitions*.json` 为准；NAND 从 offset zero 连续布局。
- AX637R ONLY_NAND AB 基线使用 KB 作为 `size` 单位，包含成对的 `sbl_a/b`、`spl_a/b`、`rtos_a/b`、`uboot_a/b`、`atf_a/b`、`optee_a/b`、`kernel_a/b`、`rootfs_a/b`，以及 `metadata`、`misc`、`ubootenv`、`userdata`。
- 非 AB resize 流程使用 `partitions_without_ab.json`；AB 场景修改对应 AB variant。不要从截图推断 offset，应解析 JSON 并计算 cumulative sizes。

## Resize 与 ownership 约束

- **扩容前先核对 NAND 颗粒总容量**：`config.mk` 的 `SBL_FLASH`/`ROOTFS_NAND_TYPE` 决定 Flash 颗粒（如 W25N04LW 为 4 Gbit / 512 MiB）。目标分区（尤其 `rootfs`）扩容后的总容量不能超过颗粒容量，否则必须先更换更大容量的 NAND 颗粒并同步 `config.mk` 相关配置。
- `size` 单位为 KB，必须是 NAND block size 的整数倍；W25N04LW 文档示例的 block size 为 256 KiB，并需保留 factory bad-block 等 NAND bad-block allowance。
- AB 模式不得随意改变 SBL size。文档化 BootROM 默认值：NAND 768 KiB，eMMC 128 KiB。
- NAND SBL 还要计入 appended HSM image；文档示例的 256 KiB SBL output 包含 128 KiB SBL 和 128 KiB HSM。
- `sbl*` 至 `rtos*` 属于 MCU-side/boot-chain partitions，默认不支持在中间插入或删除。`misc*`/`ubootenv*` 之后的 ACore partitions 可放 custom partitions。
- ONLY_NAND 将 partition-table 信息放在 `metadata`，由 AXDL 写入；ONLY_eMMC 在 offset zero 保留 1 MiB GPT area，SBL 从其后开始。
- 新 partition identifier 必须加入 `boot/uboot/u-boot-2022.10/board/axera/common/m57/common.c` 的 `main_part_id[]`；若 custom partition 携带 image，还要更新 SDK helper 的 `axp_make.sh` 路径和每个受影响的 `PLAT`。

## 传播与验证

重新生成 partition metadata/image package，并确认 generated mtdparts/XML/GPT 与 U-Boot definitions 一致。AXDL 有意重写 partition table 时使用 repartition；需要保留 persistent environment 时避免 full erase。OTA 场景保持 XML partition data 与 U-Boot 同步，并检查 `ota_repartition` 行为。

启动后验证 partition 名称/大小、mountability、rootfs/userdata 空间和预期 A/B slot。故障分析需收集 selected platform、source JSON、generated XML/mtdparts、AXDL/OTA package version、完整串口日志以及 `/proc/mtd`/block-device layout。

## 关键路径

| 主题 | 路径 |
|---|---|
| Linux 内存大小配置 | `build/platforms/axera/<platform>/config.mk`（`LINUX_MEMORY_SZ` / `SYSTEM_MEMORY_SZ`） |
| U-Boot 内存 fixup | `boot/uboot/u-boot-2022.10/arch/arm/mach-axera/m57/common.c`（`ft_system_fixup_memory`） |
| 分区 source of truth | `build/platforms/axera/<platform>/partitions*.json` |
| U-Boot 自定义 partition ID | `boot/uboot/u-boot-2022.10/board/axera/common/m57/common.c` |
| 镜像打包辅助脚本 | `scripts/axp_make.sh` |
