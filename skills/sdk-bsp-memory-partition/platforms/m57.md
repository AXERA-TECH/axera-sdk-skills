# Platform: m57

M57 DDR memory、FLASH partition 和镜像打包所需的平台事实、路径与约束。支持 NOR+NAND 和 ONLY_NAND 两种存储配置。

## DDR 与 Linux/CMM 基线

- 文档化的 1 GiB DDR 示例最多分配 Linux 384 MiB、CMM 640 MiB（large physically contiguous memory）。ATF/OPTEE 和 image-loading reservation 还会进一步细分 Linux 可见内存。
- Linux 和 CMM 的物理范围必须不重叠；实际板卡内存、固件 reservation 和模块状态必须以目标硬件为准。
- 静态配置路径：`build/platforms/axera/demo_nor_nand/config.mk`；动态调整：uboot 命令行。
- 配置项：`SYSTEM_MEMORY_SZ`（Linux + CMM 总和）、`LINUX_MEMORY_SZ`（Linux 内存大小）；两者相减即 CMM 大小。
- 若 `config.mk` 缺少这两个选项，需手动添加。

## Inline ECC 配置

- Inline ECC 跟随 fusa 开关：普通版本默认关闭，fusa 版本默认开启。
- 有两段 ECC 空间：第一段是 linux 内核空间（不可配置），第二段是 CMM ECC 空间（需跟随 DDR 大小适配）。
- **SDK 代码的 ECC 配置基于 1G DDR，修改 DDR 大小后必须同步修改 ECC 配置**：
  - 路径：`SafetyIsland/driver/ddr/ddrmc_init.h`
  - 参数：`INLINE_ECC_BLOCK_1_START` = DDR大小 - 128M
  - **警告**：DDR大小-128M/8 ~ DDR大小 这段空间是 ECC code 存储区域，DDR 硬件和软件以外不允许使用。

## 内存验证

- Linux 侧：查看 `/proc/meminfo` 确认 linux kernel 可用内存大小。
- CMM 侧：查看 CMM 模块状态确认内存配置符合预期。具体命令：

```bash
cat /proc/ax_proc/mem_cmm_info
```

关键字段：
- `+---PARTITION ... Size=524288KB(512MB)`：CMM 分区物理地址范围与总大小（对应 `SYSTEM_MEMORY_SZ - LINUX_MEMORY_SZ`），`NAME="anonymous"` 表示 anonymous 池（对应 `load_modules.sh` 的 `cmmpool=anonymous,...`）。
- `---CMM_USE_INFO: total size=... used=... remain=...`：CMM 总量 / 已用 / 剩余统计。

## Partition source of truth

- 存储配置：
  - **NOR+NAND**：双 Flash 配置（如 `demo_nor_nand`）
  - **ONLY_NAND**：单 NAND Flash 配置（如 `demo_only_nand`）
- 分区顺序：分区从 offset 0 紧密向后排布，**分区排布顺序在代码中固化**，仅需确认每个分区的 size。
- 配置文件：`build/platforms/axera/<platform>/partitions.json`（如 `demo_nor_nand/partitions.json` 或 `demo_only_nand/partitions.json`）；该文件经脚本解析后组成 mtdparts 格式字符串，通过 AXDL 工具写入 metadata 分区。uboot 启动后从该分区读取分区信息。

## mtdparts 格式示例

保存在 Flash 上的 mtdparts 格式（以 NOR+NAND 为例）：

```
nand*1#0x40000(sbl_a),0x40000(sbl_b),0x80000(spl_a),0x80000(spl_b),0x80000(atf_a),0x80000(atf_b),0x80000(optee_a),0x80000(optee_b),0x200000(uboot_a),0x200000(uboot_b),0x1400000(kernel_a)bootable,0x1400000(kernel_b)bootable
```

ONLY_NAND 配置的分区列表类似，但所有分区均在单一 NAND Flash 上。除了自定义字段（不允许传递给后一级 RTOS/Linux），其他都符合标准 Linux kernel 定义。

## Resize 与对齐约束

- `partitions.json` 中分区 size 单位为 KB。
- **对齐要求**：size 必须是 erase size 的整数倍：
  - **NOR 分区**（NOR+NAND 配置）：4K（如 GD25F64 颗粒）整数倍
  - **NAND 分区**（NOR+NAND 或 ONLY_NAND）：256K（如 W35N04JW 颗粒）整数倍
- 修改分区大小：仅需调整 `partitions.json` 中对应分区的 size，其余脚本自动适配。

## 分区创建/删除约束

**暂不支持创建和删除分区**，以免影响设备启动。
