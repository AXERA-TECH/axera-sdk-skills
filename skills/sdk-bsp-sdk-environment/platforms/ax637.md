# Platform: ax637

AX637 / AX637R SDK Linux 主机开发环境事实与规范。

## 平台说明与继承关系

AX637 / AX637R 基于 Axera M57 架构。在 Linux 主机依赖与环境配置、`sdk_unpack.sh` 源码包展开机制及基础环境验证上，AX637 承袭自 M57 体系规范。

本平台在 `routing.yaml` 中通过 `extends: m57` 继承 `platforms/m57.md` 的基础环境规范，但 AX637 强制要求补充部署 MCU RTOS (RT-Thread) 工具链及硬性路径对齐。

具体基础系统包依赖与通用解包参数可参见 [platforms/m57.md](m57.md)。

## AX637 与 M57 环境差异说明

- **工具链要求**：M57 仅需 2 套工具链；AX637 强制要求 3 套，需额外安装 MCU RTOS (RT-Thread) 工具链 `gcc-arm-none-eabi-5_4-2016q3` 并配置 `rtconfig.py` 中的 `EXEC_PATH`。
- **MCU RTOS 构建系统依赖**：SafetyIsland MCU RTOS (RT-Thread) 全部构建目标（clean/build/install）由 scons 驱动（见 `SafetyIsland/rt-thread/Makefile` 中 `MAKE := scons`），主机必须安装 scons（推荐 `sudo pip3 install scons`，scons 4.x 可用，实测 4.11.1 通过）；缺失时 SafetyIsland 阶段构建直接报 `scons: 没有那个文件或目录`（make 错误 127）。
- **包名与目标**：SDK 主包命名为 `Axera_AX637_SDK_Vx.x.x.tgz`；板级目标为 `ax637/ax637r_demo_only_nand` 与 `ax637/ax637r_demo_only_emmc`。

## 三套交叉编译工具链

AX637 SDK 构建需要部署三套不同目标与架构的交叉工具链。统一推荐解压安装至 `/usr/local`，并将可执行文件目录追加到全局环境变量（如 `/etc/profile` 或用户 `~/.bashrc`）。

| 工具链用途 | 精确版本 / 归档名 | 官方/推荐下载地址 | 默认安装路径 | 验证命令与输出 |
|---|---|---|---|---|
| **AArch64 Linux/App** | `gcc-arm-9.2-2019.12-x86_64-aarch64-none-linux-gnu.tar.xz` (gcc 9.2.1 20191025) | `https://developer.arm.com/-/media/files/downloads/gnu-a/9.2-2019.12/binrel/gcc-arm-9.2-2019.12-x86_64-aarch64-none-linux-gnu.tar.xz` | `/usr/local/gcc-arm-9.2-2019.12-x86_64-aarch64-none-linux-gnu` | `aarch64-none-linux-gnu-gcc -v` |
| **MCU Boot ARM32** | `gcc-linaro-7.5.0-2019.12-x86_64_arm-linux-gnueabi.tar.xz` | `http://releases.linaro.org/components/toolchain/binaries/7.5-2019.12/arm-linux-gnueabi/gcc-linaro-7.5.0-2019.12-x86_64_arm-linux-gnueabi.tar.xz` | `/usr/local/gcc-linaro-7.5.0-2019.12-x86_64_arm-linux-gnueabi` | `arm-linux-gnueabi-gcc -v` |
| **MCU RTOS/RT-Thread ARM32** | `gcc-arm-none-eabi-5_4-2016q3-20160926-linux.tar.bz2` | `https://developer.arm.com/-/media/Files/downloads/gnu-rm/5_4-2016q3/gcc-arm-none-eabi-5_4-2016q3-20160926-linux.tar.bz2` | `/usr/local/gcc-arm-none-eabi-5_4-2016q3` | `arm-none-eabi-gcc -v` |

### 环境变量配置参考
在 `/etc/profile` 或 `~/.bashrc` 末尾添加：
```sh
export PATH="/usr/local/gcc-arm-9.2-2019.12-x86_64-aarch64-none-linux-gnu/bin:$PATH"
export PATH="/usr/local/gcc-linaro-7.5.0-2019.12-x86_64_arm-linux-gnueabi/bin:$PATH"
export PATH="/usr/local/gcc-arm-none-eabi-5_4-2016q3/bin:$PATH"
```
生效后分别执行对应的 `-v` 命令确认三套编译器均可正常调用。

## RT-Thread 工具链路径对齐检查

> **构建系统前置依赖**：RT-Thread 的全部构建目标（clean/build/install）由 scons 驱动（`SafetyIsland/rt-thread/Makefile` 中 `MAKE := scons`）。执行路径对齐检查前，须先在主机安装 scons（推荐 `sudo pip3 install scons`，scons 4.x 可用，实测 4.11.1 通过）；缺失时 `make PLAT=<target> all install axp` 在 SafetyIsland 阶段直接失败，报 `make: scons: 没有那个文件或目录`（错误 127）。

MCU RTOS（RT-Thread）编译时除了 `PATH`，还会严格以配置文件中的显式路径为准：
1. 检查目标平台配置 `build/platforms/<PLAT>/config.mk` 中定义的 `RTT_CONFIGS`（例如 `configs_ax637` 或 `configs_ax637r`）。
2. 打开对应的 `SafetyIsland/rt-thread/bsp/m57/configs_<value>/rtconfig.py`。
3. 确认或设置 `EXEC_PATH` 变量指向工具链真实绝对路径（通常为 `/usr/local/gcc-arm-none-eabi-5_4-2016q3/bin` 或 `/usr/local/gcc-arm-none-eabi-5_4-2016q3`）。该步骤为 Source-of-truth 检查。

## SDK 解包与离线恢复（AX637 专有命名）

1. **主包展开**（AX637 主包命名，其余解包流程与 M57 一致）：
   ```sh
   tar -xvf Axera_AX637_SDK_Vx.x.x.tgz
   cd Axera_AX637_SDK_Vx.x.x
   ```
2. **源码拉取与打补丁、离线参数（`-k`/`-u`/`-a`/`-o`）及 `sdk_clean.sh` 清理防错说明**：
   与 M57 完全一致，公共说明统一参见 [platforms/m57.md](m57.md) 的「SDK 解包与源码获取（sdk_unpack.sh）」章节，此处不再重复。

## 规范自闭环说明

基础主机环境（apt 依赖含 `liblz4-tool`、Python 依赖、dash 切换）、AArch64 与 Linaro ARM32 工具链及 `sdk_unpack.sh` 解包机制均继承自 [platforms/m57.md](m57.md)；本文件自闭环包含 AX637 / AX637R 特有事实：第三套 MCU RTOS (RT-Thread) 工具链、scons 构建系统依赖、`EXEC_PATH` 路径对齐及 AX637 主包命名。
