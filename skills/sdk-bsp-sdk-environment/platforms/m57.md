# Platform: m57

Axera M57 架构层 SDK 开发主机环境与工具链事实与规范。

## 主机操作系统与依赖包要求

推荐基线为 **Ubuntu 20.04 LTS (x86_64)**。

### 1. 基础系统工具与库
执行以下 apt 安装命令：
```sh
sudo apt-get update
sudo apt-get install -y make build-essential gcc g++ gdb libc6:i386 lib32stdc++6 lib32z1 \
    zlib1g-dev libncurses5-dev libncursesw5-dev ncurses-term e2fsprogs mtd-utils texinfo \
    texlive gawk libssl-dev openssl bc bison flex u-boot-tools device-tree-compiler liblz4-tool
```

> **注意**：
> - 在旧版或特定 Ubuntu 发行版上，务必保留 `lib32z1` 和 `u-boot-tools`；缺少 32 位 `libz.so.1` 极易导致 U-Boot 或镜像制作工具构建失败。
> - `liblz4-tool` 提供的 shell `lz4` 命令与 Python 依赖中的 `pip3 install lz4`（Python 模块）互相独立，不能替代。
> - 系统需配置 dash 切换为 bash 兼容行为：运行 `sudo dpkg-reconfigure dash` 并选择 **No**（Buildroot 与部分构建脚本强依赖 `/bin/sh` 为 bash 行为）。

### 2. Python 依赖
```sh
sudo apt-get install -y python3-pyelftools python3-pip
pip3 install openpyxl lxml lz4 pycryptodome rsa sympy
```

## 交叉编译工具链

M57 SDK 构建需要部署对应目标与架构的交叉工具链。统一解压安装至 `/usr/local`（或 `/usr/local/ARM-toolchain`），并将可执行文件目录追加到全局环境变量（如 `/etc/profile` 或用户 `~/.bashrc`）。

| 工具链用途 | 精确版本 / 归档名 | 官方/推荐下载地址 | 默认安装路径 | 验证命令与输出 |
|---|---|---|---|---|
| **AArch64 Linux/App** | `gcc-arm-9.2-2019.12-x86_64-aarch64-none-linux-gnu.tar.xz` (gcc 9.2.1 20191025) | `https://developer.arm.com/-/media/files/downloads/gnu-a/9.2-2019.12/binrel/gcc-arm-9.2-2019.12-x86_64-aarch64-none-linux-gnu.tar.xz` | `/usr/local/gcc-arm-9.2-2019.12-x86_64-aarch64-none-linux-gnu` | `aarch64-none-linux-gnu-gcc -v` |
| **MCU Boot ARM32** | `gcc-linaro-7.5.0-2019.12-x86_64_arm-linux-gnueabi.tar.xz` | `http://releases.linaro.org/components/toolchain/binaries/7.5-2019.12/arm-linux-gnueabi/gcc-linaro-7.5.0-2019.12-x86_64_arm-linux-gnueabi.tar.xz` | `/usr/local/gcc-linaro-7.5.0-2019.12-x86_64_arm-linux-gnueabi` | `arm-linux-gnueabi-gcc -v` |

### 环境变量配置参考
在 `/etc/profile` 或 `~/.bashrc` 末尾添加：
```sh
export PATH="/usr/local/gcc-arm-9.2-2019.12-x86_64-aarch64-none-linux-gnu/bin:$PATH"
export PATH="/usr/local/gcc-linaro-7.5.0-2019.12-x86_64_arm-linux-gnueabi/bin:$PATH"
```
生效后分别执行对应的 `-v` 命令确认编译器均可正常调用。

## SDK 解包与源码获取（sdk_unpack.sh）

1. **展开主包**：
   ```sh
   tar -xvf Axera_M57_SDK_Vx.x.x.tgz
   cd Axera_M57_SDK_Vx.x.x
   ```
2. **源码解包脚本（在线模式）**：
   在 SDK 根目录下执行 `./sdk_unpack.sh`。默认情况下脚本会自动从预设服务器拉取源码并自动打 Axera patch：
   - Linux 内核: `linux-6.1.83.tar.gz`
   - U-Boot: `u-boot-2022.10.tar.bz2`
   - ATF: `arm-trusted-firmware-2.8.0.zip`
   - OP-TEE: `optee_os-3.21.0.zip`
3. **离线恢复与手动指定源码包（网络受限时）**：
   当默认下载 URL 无法访问、失效或在隔离内网时，先手动获取对应版本的归档压缩包，通过指定参数解包：
   ```sh
   # 官方/镜像下载参考：
   # Linux Kernel 6.1.83: wget -t 5 https://mirror.tuna.tsinghua.edu.cn/kernel/v6.x/linux-6.1.83.tar.gz
   # U-Boot 2022.10: wget -t 5 https://ftp.denx.de/pub/u-boot/u-boot-2022.10.tar.bz2
   # ATF 2.8.0: wget -t 5 https://github.com/ARM-software/arm-trusted-firmware/archive/refs/tags/v2.8.0.zip
   # OP-TEE 3.21.0: wget -t 5 https://github.com/OP-TEE/optee_os/archive/refs/tags/3.21.0.zip

   ./sdk_unpack.sh -k /path/to/linux-6.1.83.tar.gz \
                   -u /path/to/u-boot-2022.10.tar.bz2 \
                   -a /path/to/arm-trusted-firmware-2.8.0.zip \
                   -o /path/to/optee_os-3.21.0.zip
   ```
4. **GitHub 源码包直连失败时的加速下载（ATF / OP-TEE）**：
   ATF 与 OP-TEE 归档托管在 GitHub（实际下载经 `codeload.github.com`）。国内网络直连速度仅约 100KB/s 且极不稳定，`wget --timeout=30` 读取超时失败后会在目标路径残留 0 字节 zip，导致后续 `unzip` 解包报错中断。此时先删除残留的 0 字节文件，再从官方地址重试；网络受限时使用所在组织批准的镜像或代理，不使用来源不明的公共加速服务：
   ```sh
   rm -f /path/to/arm-trusted-firmware-2.8.0.zip /path/to/optee_os-3.21.0.zip
   wget -t 5 -O /path/to/arm-trusted-firmware-2.8.0.zip https://github.com/ARM-software/arm-trusted-firmware/archive/refs/tags/v2.8.0.zip
   wget -t 5 -O /path/to/optee_os-3.21.0.zip https://github.com/OP-TEE/optee_os/archive/refs/tags/3.21.0.zip
   sha256sum /path/to/arm-trusted-firmware-2.8.0.zip /path/to/optee_os-3.21.0.zip
   ```
   下载后校验：`sha256sum` 结果须与团队记录或可信环境中下载的同版本归档一致；ATF zip 约 9.4MB、OP-TEE zip 约 5.3MB，`unzip -t` 完整性通过，且解压顶层目录为 `arm-trusted-firmware-2.8.0/` 与 `optee_os-3.21.0/`（与 `sdk_unpack.sh` 预期一致），再通过 `-a` / `-o` 参数传入。Linux 内核（清华镜像）与 U-Boot（`ftp.denx.de`）不受此问题影响。
5. **清理防错说明**：
   不要随意运行 `./sdk_clean.sh`。该脚本为 `sdk_unpack.sh` 的逆向操作，会强制清除所有由 `sdk_unpack.sh` 生成的文件及源码目录。如有本地修改或私有数据，必须先行备份。
