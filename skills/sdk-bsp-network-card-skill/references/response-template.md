# 诊断输出模板

先写代码基线和网络层级；缺失项写“未提供，不能判断”，不要补猜：

```text
结论等级：已确认 / 高可信候选 / 待验证
网络层级：链路（PHY/MAC）/ IP-DHCP / TCP 服务 / 吞吐
现象：保留用户原始日志和时间点
依据：日志、代码路径、匿名案例或 A/B 结果（逐条对应）
机制：只解释被证据支持的机制
验证：给出最小化命令、预期观察和对照变量
边界：明确不能由当前证据推出的结论
下一步：按优先级列出补充日志、硬件或网络协作项
```

输出至少包含一个“反证条件”：例如 CUBIC 对照仍低速时，不能继续把问题归因于 BBR；温度和 PHY 驱动能力 A/B 无差异时，不能继续把问题归因于 TX 电流。

常见判定：只有 `NO-CARRIER` 先确认 PHY 探测/复位/MDIO/时钟/对端；link 反复变化先收集温度、对端、线缆和眼图；carrier 正常但无 IP 验证 DHCP/静态配置/路由；有 IP 但 telnet 失败验证 `ss -lntp`、端口、路由和防火墙；iperf 低而 ping 正常优先做 BBR/CUBIC 与 `CONFIG_HZ` 对照。
