# AX615 网络匿名案例

以下案例只保留可公开复用的现象、代码机制和验证边界。案例标签不是工单号，不能替代当前设备证据。

## NET-CASE-A：ping 正常但 TCP 吞吐偏低

- **现象**：链路与 ping 正常，iperf 吞吐约 10 Mbps；切换 TCP 拥塞算法后吞吐明显变化。
- **机制候选**：BBR 与内核计时精度、`CONFIG_HZ` 的组合可能使速度控制异常；调整 `bbr_full_bw_cnt` 只能用于验证，不能作为通用修复。
- **验证**：记录拥塞算法、`CONFIG_HZ`、iperf 方向/并发/窗口、CPU 和 `ethtool -S`；保持其他变量不变做 BBR/CUBIC A/B。若两者无差异，应推翻拥塞算法方向。
- **边界**：该案例不能解释 link down、无 IP 或服务端口未监听。

## NET-CASE-B：低温概率性无法建链

- **现象**：常温链路或眼图正常，低温连接固定对端时概率性无法 link；改变 PHY TX 驱动相关配置后复现率或眼图变化。
- **机制候选**：PHY 模拟裕量、板级无源器件和对端组合可能共同影响低温建链。
- **验证**：记录原始寄存器、温度、对端、线缆、眼图和错误计数；在线寄存器写入只做受控 A/B，验证后通过重启或重新初始化恢复。
- **边界**：某一寄存器值不是所有板卡的通用配置。温度和驱动能力 A/B 无差异时，应推翻 TX 驱动方向。

## 快速匹配

| 现象 | 首要证据 | 不能直接下的结论 |
|---|---|---|
| `NO-CARRIER`/`Link is Down` | `ethtool`、PHY 状态、MDIO/复位日志 | 不能直接断定 PHY 损坏 |
| 反复 linkup/linkdown | 时间序列、温度、对端、眼图、计数器 | 不能直接套用某个寄存器值 |
| carrier 有、没有 IP | DHCP/静态配置、`ip addr`、抓包 | 不是必然的链路故障 |
| 有 IP、telnet 不通 | 路由、监听、端口、防火墙 | 不是必然的 PHY 故障 |
| ping 正常、iperf 低 | BBR/CUBIC、`CONFIG_HZ`、窗口、错误计数 | 不是必然的网卡硬件问题 |
